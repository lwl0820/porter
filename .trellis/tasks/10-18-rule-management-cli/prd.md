# 非 Docker 环境双语规则管理命令行工具

## 目标与价值

为原生部署提供与管理员规则权限一致的命令行入口，让服务器维护者直接在本机终端完成转发规则的增删改查，并与 Web 管理端实时保持一致。

## 背景与已确认决策

- 用户要求：命令行支持中文、英文，仅在非 Docker 环境有效，本期只做规则管理，不做用户和套餐管理。
- 用户已回复“按你推荐”，确认本机 root/sudo 免登录，无须输入 Web 管理员账号密码。
- 用户进一步明确：未指定 `--lang` 时，第一步必须选择语言，不得直接采用默认语言。
- 用户进一步要求：同时支持交互方式和参数方式管理规则，两种方式均须完整覆盖增删改查。
- 实施前主程序只有服务启动和版本查询入口；规则由同一进程协调 SQLite、运行态和监听，SQLite 使用单实例排他锁。
- 现有管理员能管理任意归属规则，但仍遵守用户端口、配额和规则校验约束。
- 代码依据和位置见 `research/现有实现.md`；本任务作为一个完整交付，不拆分子任务。

## 需求

### R1：本机管理员访问

- 仅支持 Linux 原生部署；执行规则命令须为 root 或通过 sudo 提权。
- 命令操作运行中的本机 Porter 服务，无须 Web 登录，也不自动读取或打印管理员密码。
- 非 root 调用拒绝；服务未运行时给出所选语言的可执行提示，不自动启动服务或离线写库。
- 本机访问入口不得通过 Web 管理监听端口对外暴露。

### R2：规则增删改查

- 使用现有程序：`porter rules` 进入交互菜单，`porter rules add|list|get|update|delete` 通过参数直接执行；保持不带任何子命令启动服务以及 `--version` 的现有行为。
- 交互菜单提供创建、规则列表、查看详情、修改、删除和退出；引导填写创建字段，通过列表选择规则并显示详情，修改时允许保留原值。删除前明确显示所选规则并确认，取消或返回不得提交变更。
- 参数方式提供完整字段后直接执行，不进入管理菜单、不逐项追问缺失字段；缺少必需参数时按所选语言报错。脚本显式指定 --lang 后全程无交互，未指定时仍须先选择语言。
- 新增规则支持名称、TCP/UDP/TCP+UDP、监听 IP/端口、目标主机/端口、启用状态及展示统计开关。默认启用、展示统计关闭，与现有规则创建行为一致。
- 创建默认归属管理员，可通过已有用户的稳定 ID 指定归属；本期不增加查询或管理用户、套餐的命令。
- 列表默认全部规则，展示 ID、名称、协议、监听、目标、启用状态、运行状态、归属、版本；可按归属 ID 过滤。详情包括规则配置、运行状态、版本和现有统计。
- 修改只改变明确传入的字段，保留未传字段及规则归属；启用/停用由修改命令处理。
- 修改和删除按稳定规则 ID 定位；沿用版本冲突保护，不能静默覆盖并发变更。
- 删除指定 ID 后即时释放相关监听和会话；参数方式不设置交互式二次确认，便于脚本调用，交互方式按菜单流程确认后删除。
- 所有变更沿用规则服务、持久化、审计及错误回滚语义；只改名称继续保留连接。

### R3：双语及输出

- 未指定 `--lang` 时，规则命令及 CLI 帮助先展示“语言 / Language”，供选择中文或 English；选择完成后才进行命令校验、权限检查、服务连接和规则操作。每次未指定参数都需选择，不沿用上次语言，也不根据系统语言静默跳过。
- 显式指定 `--lang zh-CN|en` 时跳过语言选择。帮助、参数校验、权限提示、操作结果、服务端业务错误及状态名称随所选语言切换。
- 无可用交互终端且未指定 `--lang` 时，以双语提示要求提供该参数并退出，不执行操作；无效选择重试，取消或输入结束退出且不执行操作。脚本和无人值守使用必须显式指定语言。
- 语言选择提示与输入通过控制终端进行，不能混入标准输出或消费规则命令的管道输入；JSON 模式同样先完成语言选择。服务默认启动和既有 `--version` 行为保持不变。
- 交互菜单、逐项提示、规则选择、确认和错误恢复均支持所选语言；一次交互会话只选择一次语言。交互管理需要可用控制终端，即使指定语言，无终端时也不得自动改为另一种操作模式。
- 命令名、参数名、协议值、ID 等稳定标识不翻译；用户输入的名称和目标地址不翻译。
- 默认可读表格/详情，提供 `--json` 输出供脚本读取；JSON 的字段名、状态码和错误码保持稳定。
- 成功退出码为 0；操作失败为 1；用法/参数错误为 2。结构化输出写标准输出，失败提示写标准错误，避免混入服务日志。

### R4：部署边界

- Docker 镜像中的规则命令不可用，也不启动本机控制入口；将原生程序放入可识别的 Docker 运行环境同样拒绝规则管理。
- 原生发行包仍包含同一个 porter 程序，默认通过 `sudo /opt/porter/porter rules ...` 使用；自定义安装目录使用对应程序路径。
- 支持直接运行原生二进制时指定本机控制路径；不要求加入 systemd 才能执行规则操作。
- 不新增全局 PATH 链接或独立安装工具；更新中英文使用说明，并验证安装、卸载和容器运行兼容性。

## 范围外

用户管理、套餐管理、端口池管理、远程 CLI、Web 凭据登录、离线写库、批量导入导出、独立重试命令及流量清零命令。规则启用及展示统计开关仍属于可修改字段。

## 风险与延后项

- 操作依赖运行中的服务；不提供停机编辑能力。
- 交互管理必须有终端；参数管理未指定语言同样需要终端，自动化脚本须使用 `--lang`。
- 部署升级需同时更新服务程序和执行命令的程序；旧服务没有本机入口时明确提示升级/重启。
- 容器运行识别使用构建限制及运行标记共同防护；不承诺识别人为隐藏所有容器标记的环境，Docker root 与宿主 root 的隔离仍由宿主配置保证。
- 本机 root 已具备系统管理员权限，此入口不扩大普通系统用户的权限。
- 发行版宿主及双架构真实运行结果按实际环境记录，不用交叉编译代替实测。
