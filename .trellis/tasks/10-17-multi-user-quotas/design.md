# 技术设计：多用户、套餐及配额

## 设计目标与边界

本设计实现本任务 PRD 的 R1–R21。沿用 Go HTTP、SQLite、现有规则服务和转发引擎、Vue 页面及中英文系统，不引入新的服务或分布式组件。

这是一个跨认证、持久化、数据路径和界面的完整功能。用户隔离、端口约束和配额必须共同生效才能验收；采用同一任务分阶段交付，不拆成会单独启用但缺少资源约束的用户功能。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| internal/model | 用户、套餐、系统配置、用户周期用量及接口输入输出类型；规则增加 owner_id。 |
| internal/store | 增量迁移、账号凭据、套餐、端口配置、分配和周期用量的事务存取；禁止响应泄露凭据。 |
| internal/auth | 环境变量管理员及数据库普通用户分别认证，带用户 ID/角色/所属端的会话；两端独立 Cookie、CSRF、登出和过期，登录限流共享全局保护。 |
| internal/quota（新增） | 无 HTTP 依赖的周期计算、四种计费、用户级共享计量和耗尽信号，可控时间便于验证。 |
| internal/rules | 统一协调用户/套餐/配置及规则变更，检查操作者与资源归属、分配端口、加载额度、停止/恢复用户规则、保存周期累计。可按 accounts.go、quota.go 等文件分离职责。 |
| internal/forward | 在成功写出点累计独立用户用量；转发前检查共享额度状态；不在数据路径操作数据库或取得服务锁。 |
| internal/httpapi | 独立注册 admin、user 认证及业务路由，各自进行会话和角色守卫；管理规则 DTO 与所属用户过滤，严格 JSON、统一错误、Origin/CSRF 及 revision 保护。 |
| web/src | 管理端和用户端独立入口及应用壳；管理端全部规则、所属用户、用户筛选和代操作；两端复用规则组件、格式化与双语基础能力。 |

## 数据模型与迁移

新增版本 4 的 SQL 迁移，保留既有 001–003 迁移；不得修改历史迁移达到升级效果。

- users：稳定 id、唯一 username、role、普通用户密码派生编码、plan_id、port_start/port_end、created_at。管理员使用固定系统标识，plan 和端口段为空，凭据仍来自环境变量；不将管理员明文密码写入数据库。
- plans：id、name、port_count、traffic_limit_bytes、accounting_mode、reset_mode、reset_day、created_at。本期套餐只创建和读取，既有用户引用其套餐，无需设计在线同步变更。
- system_settings：单条端口池配置，初始未配置，含起止值、revision 和 updated_at；未配置时管理员自有规则可运行，普通用户创建返回明确配置错误。
- user_ports：普通用户分配的数字端口及 user_id，port 为主键；和 users 中的范围在一个事务插入。最多 65535 条，便于用数据库唯一性保护独占且支持并发分配。
- user_usage：user_id 主键、cycle_start、cycle_end、upload_bytes、download_bytes、周期版本。只维护当前周期，不提供历史账单。
- rules：增加 owner_id，旧记录回填为稳定系统管理员 ID；保留原有 rule_traffic 外键和记录。

管理员身份初始化必须在任何规则恢复前完成。环境变量管理员改名时维持同一用户 ID；若新管理员名与普通用户重名，明确拒绝启动，不能静默接管普通用户身份。普通用户密码用带独立随机盐和参数编码的标准密码派生算法保存，不沿用当前单次 SHA-256 作为密码存储；实施时核实所选标准库 API 并对正确/错误密码进行验证。

SQLite 约束验证角色、正整数额度、端口范围和枚举。新表使用独立名字，不重建既有 rules 表以免破坏现有自定义索引、触发器。迁移与管理员归属初始化必须可失败回滚；不允许恢复了一半的数据开始监听。

## 独立后台、认证与规则归属

两个后台仍由同一个 Porter 进程和数据卷提供，页面与接口独立，不新增监听端口或要求独立域名：

| 端 | 页面入口 | 登录页 | API 前缀 |
| --- | --- | --- | --- |
| 管理端 | /admin/ | /admin/login | /api/admin |
| 用户端 | /user/ | /user/login | /api/user |

管理端和用户端使用独立前端入口、应用壳和导航，允许复用底层组件和业务服务。根地址 / 跳转到 /admin/。web/embed.go 当前直接使用文件服务器、不支持应用深链接；实施时增加两个明确路径范围的首页映射，刷新 /admin/login、/user/login 等合法页面正常，不能把 /api/* 的错误兜底成 HTML。

登录与 session 响应包含 user_id、username、role、csrf_token。内存会话额外记录所属端，仍在进程重启后失效。管理登录仅接收管理员，用户登录仅接收普通用户；错误账号或角色统一认证失败，不能把一端登录作为访问另一端的凭据。

Cookie 分别为 porter_admin_session（Path=/api/admin）及 porter_user_session（Path=/api/user），保留 HttpOnly、SameSite=Strict 和配置化 Secure。每端有独立 CSRF token、前端内存客户端及失效回调；重新登录和退出只撤销该端所呈现会话。同一浏览器可同时登录两端，任何业务接口只读取自身端 Cookie，并核对服务端会话的端与角色，不能只相信 Cookie 名。两端登录尝试共用全局限流计数，避免拆分入口放大可尝试次数。

普通用户列表强制按自身 ID 查询，不提供 owner_id 过滤或写入能力；其他用户规则返回 404，且服务层先验证归属再校验版本，不暴露他人 revision。管理接口直接以管理员操作者调用同一底层规则服务，默认读取全部归属，通过 owner_id 查询参数筛选用户。管理员过滤条件不传入用户端处理路径。

管理列表和操作响应使用 AdminRule：包含完整 Rule 及 owner={id,username,role}，所属账号来自服务端用户资料，不能从客户端名称推断；用户端 Rule 仅包含自身资源契约。管理端为任意已存在账号新增规则时使用独立 AdminRuleCreateInput，额外接收 owner_id 并验证账号存在；默认可选择管理员本人。规则更新不接受 owner_id，不提供归属转移。普通用户的 RuleInput 严格拒绝 owner_id 等未知字段。

管理员可直接新增、编辑、删除、启停、重试或重置任意用户规则展示统计；创建/编辑/启用/重试都按规则所属账号检查端口和额度，不冒用用户会话，不把管理员身份作为绕过套餐约束的条件。日志区分操作者与所属用户，不能记录密码、哈希或 token。

两端保留 Origin、CSRF、登录限流、严格 JSON、If-Match 和原有写入失败回滚；共享逻辑在服务层复用，HTTP 注册与前端客户端独立。旧共享 /api/auth/*、/api/rules* 和 /api/account 业务路由移除并返回结构化 404，避免留下绕过端隔离的兼容入口；更新所有前端、测试、文档和冒烟脚本。

## 端口分配与操作顺序

用户创建、系统范围变更与规则配置写入通过统一服务操作锁协调，防止管理员新增规则与用户分配抢占同一数字端口；不能只靠 HTTP handler 做先查询后插入。

创建用户顺序：校验身份和输入 → 校验套餐和配置 → 枚举当前范围中已分配端口、所有管理员规则数字端口及管理端口 → 从小到大寻找第一段足够长的连续空闲数字 → 单事务创建账号、范围、user_ports 和初始 user_usage → 提交后更新服务内存快照 → 返回不含凭据的用户资料。

缺少连续段、重名或任意存储失败则回滚。外部系统 socket 不属于持久化分配依据，实际规则保存和恢复仍走原有监听预备逻辑。

设置范围要求 1 ≤ start ≤ end ≤ 65535，使用 revision 防止并发覆盖。范围调整不删除 user_ports；分配新用户时只在新池内寻找空闲段。管理员新规则不能落在 user_ports 的任何数字端口，即使使用不同 IP 或协议；保留原有逻辑协议交集、通配地址、管理监听、自身回环等校验。

## 周期计算与转换

所有存储时间为 UTC；使用周期开始时刻作为稳定键，时间区间为左闭右开。重置日计算从原始 UTC 日号和目标年月出发，取 min(锚点日, 当月最后一天)，不能对上一次截断日期逐月相加。

首次开户的周期从开户时刻开始，到下一个重置点结束，立即获得完整额度。若开户恰逢重置点，该点为起点，下个月为结束点。自然月模式锚点为 1，固定日模式用 reset_day，开户模式用 created_at.UTC().Day()。

启动、周期协调定时器及数据准入时均识别过期周期；后台定时不能是唯一校验点。周期到期时短暂暂停该用户新的写入准入，独立协调过程事务推进周期，再开放当前周期并恢复 enabled=true 且因额度暂停的规则。仍正常运行的规则不因清零强制断开连接，原有监听错误也不作为额度暂停自动恢复。

周期代切换期间的在途完成按写入成功时刻归属对应周期，并保留下一周期的暂存增量；持久化和发布新计量基线不能覆盖这些增量。协调过程不持有用量短锁访问数据库，数据路径不等待服务锁。用可控时钟和阻塞写入测试验证边界，必要时等待周期事务完成后再继续准入。

数据库重置提交失败时不得先放行新额度；保持受影响用户暂停并记录错误，之后重试。跨过多个周期时直接计算当前周期，不循环补发额度。系统时钟回退不回滚已持久化周期，不重新发放旧周期额度。

## 用户级计量及实时停转发

每位普通用户在同一周期共享一个用量对象，全部规则、协议、监听器和会话引用它；管理员自有规则无用户额度对象。该对象保存 U、D、计费模式、额度、周期键及耗尽状态，短锁内按 PRD 四种公式计算，保护加法溢出。

转发写出点只按实际成功的 n 增量计量；展示统计仍由原 traffic_enabled 控制，套餐计量始终生效。计量对象达到额度后立即标记耗尽并发送带 user_id/周期键的信号，后续数据准入立即拒绝；不等待定时保存、页面刷新或已有连接自然结束。

独立协调过程核对周期和对象身份，在服务操作锁内停止该用户全部运行组，包括组合规则的两侧和已有 TCP/UDP 会话。转发协程只通知，不能同步调用等待自身退出的 Stop。并发在途写入可能在耗尽标记前已经发出；承诺实时耗尽后主动停止，不把它描述为逐字节完全无超额的整形器，也不人为增加固定轮询超额窗口。

enabled 表示用户配置意图，耗尽不能批量写成 enabled=false。规则状态新增 quota_exceeded；用户手动停用优先显示 disabled。新建 enabled=true、启用、改动启用规则或重试在用量耗尽时返回 quota_exceeded，允许停用、删除和清零展示统计；编辑停用规则可保存合法配置但不能启动。

## 保存间隔、失败与退出

新增 PORTER_TRAFFIC_FLUSH_INTERVAL，默认 5s，沿用 Go duration 输入和现有配置校验范围 1ms–24h。未设置或空值使用默认；非法、非正及越界值拒绝启动，文档说明过短增加磁盘负担、过长扩大异常退出丢失窗口。

统一保存调度使用该间隔，独立控制规则累计和用户用量快照的批量保存。每秒速度采样、UTC 周期检查和前端五秒刷新不依赖它。若需构造器兼容，使用明确的 service options 或配置结构，原有测试默认仍为五秒。

持久化快照须带用户周期键；周期切换、规则展示清零、删除与保存由服务顺序协调，数据库 WHERE 周期键避免旧快照覆盖新周期。仅成功提交后更新持久化基线。失败保留内存用量并记录错误，之后重试；持续保存失败不限制在一个保存间隔内丢失，运行中仍按内存额度断流。

正常退出先拒绝新管理写操作、停调度、停止转发并等待计量结束，再最终保存两个账本，最后关闭数据库。幂等关闭及错误向上传递保持有效；强制退出遵循用户接受的未保存增量可能丢失约束。

## HTTP 契约草案

| 接口 | 身份 | 语义 |
| --- | --- | --- |
| POST /api/admin/auth/login | 管理端管理员凭据 | 创建管理端会话，仅设置管理 Cookie。 |
| GET /api/admin/auth/session；POST /api/admin/auth/logout | 管理端管理员会话 | 恢复/注销管理端身份，不影响用户端。 |
| POST /api/user/auth/login | 用户端普通用户凭据 | 创建用户端会话，仅设置用户 Cookie。 |
| GET /api/user/auth/session；POST /api/user/auth/logout | 用户端普通用户会话 | 恢复/注销用户端身份，不影响管理端。 |
| GET /api/user/account | 用户端普通用户会话 | 本人的套餐、端口和当前周期用量。 |
| GET /api/admin/rules?owner_id=<用户ID> | 管理端管理员会话 | 默认全部，指定 owner_id 后按归属过滤，响应为带 owner 的 AdminRule 列表。 |
| POST /api/admin/rules | 管理端管理员会话 | 为 owner_id 指定的已有账号新增规则，返回 AdminRule。 |
| PUT、DELETE /api/admin/rules/{id} | 管理端管理员会话 | 直接编辑/启停/删除任意用户规则，不转移归属。 |
| POST /api/admin/rules/{id}/retry、/traffic/reset | 管理端管理员会话 | 任意规则重试或清零展示统计，不清零套餐账本。 |
| GET、POST /api/user/rules | 用户端普通用户会话 | 本人规则列表、创建，owner 由会话确定。 |
| PUT、DELETE /api/user/rules/{id} | 用户端普通用户会话 | 本人规则编辑/启停/删除。 |
| POST /api/user/rules/{id}/retry、/traffic/reset | 用户端普通用户会话 | 本人规则重试或清零展示统计。 |
| GET、POST /api/admin/plans | 管理端管理员会话 | 列表、创建套餐。 |
| GET、POST /api/admin/users | 管理端管理员会话 | 列表、创建普通用户并原子分配端口，列表含套餐及用量。 |
| GET、PUT /api/admin/settings | 管理端管理员会话 | 读取、更新端口池，PUT 携带 If-Match。 |

owner_id 筛选为空或省略表示全部，使用稳定用户 ID 精确过滤；合法但不存在的用户 ID 返回空列表。管理员本人也作为列表所属账号和筛选选项，不依赖当前普通用户列表凑出归属。现有名称/地址搜索、协议及状态筛选可在管理端按已校验结果组合，不能因切换用户而丢失其他筛选。

套餐输入：name、port_count、traffic_limit_bytes（十进制正整数字符串）、accounting_mode、reset_mode、reset_day。计费枚举 both/max/upload/download；重置枚举 calendar_month/anniversary/fixed_day。仅 fixed_day 接受 1–31 的 reset_day，其他模式要求 null 或省略，拒绝无效组合。

用户创建输入：username、password、plan_id。分配段、角色、创建时间和用量均由服务端生成。密码只存在创建输入和后端派生过程中，不出现在用户列表、审计日志或响应。

用量响应包含 cycle_start、cycle_end、upload_bytes、download_bytes、used_bytes、limit_bytes、exceeded；字节字段均为非负十进制字符串。端口为整数，UTC 时间为 RFC3339。新建成功 201，非法字段 400，无本端有效会话 401，端或角色不符 403，跨用户资源 404，重名/端口不足/额度耗尽 409，版本不符 412，存储失败 500；使用统一 error.code/message/fields。规则更新、删除、重试和展示清零仍携带 If-Match；所有写入仍校验本端 CSRF 和 Origin。

## 前端方案

- 使用两个独立前端入口和根组件：管理应用负责自己的登录、全部规则、套餐、用户和系统配置；用户应用负责自己的登录、本人规则及资源概览。可以采用 Vite 多入口产物，共用语言、样式、Modal 和规则组件，不引入仅为拆端而增加的服务。
- API 层保留唯一请求和响应校验实现，但以工厂创建 adminApi 与 userApi，分别固定 /api/admin、/api/user；CSRF、会话和 unauthorized 回调存于各自客户端实例。禁止保留一个可切换角色且共享 token 的全局 api 对象。
- 管理规则表格增加所属用户列，窄屏卡片也显示；顶部用户筛选默认“全部用户”，包含管理员本人和普通账号，值为用户 ID。切换用户时请求管理列表，取消旧请求并递增请求版本；迟到结果、错误和轮询不能覆盖当前用户筛选。
- 用户筛选与原有搜索、协议和状态筛选组合；管理端沿用规则编辑、删除确认、启停、重试和展示清零交互。新增规则时选择归属账号；编辑已有规则显示归属但不允许转移，范围预览与校验按所属用户计算。
- 两端 Session 解码都校验 user_id 和匹配的 role；401 只复位本端页面、对话框、请求和客户端状态。独立页面入口不意味着服务端信任前端路由，后台角色守卫始终有效。
- 套餐表单含数量、额度（明确 GiB）、四种计费、三种重置，选择固定日才显示 1–31；新增用户表单选择套餐并展示资源预览，提交成功展示实际分配范围。
- 用户概览展示套餐、范围、上下行、计费用量/额度、额度耗尽提示和 UTC 下次重置；不能将单向误标成只上传或只下载。
- RuleEditor 复用表单实现并接收所属账号的端口边界；服务端仍为权威。quota_exceeded 与用户手动停用及监听错误分别展示。
- 用户管理不展示编辑、删除等本期未支持操作。写操作成功更新对应快照并失效旧请求；管理员操作后用户端在下一次刷新同步，用户不能以旧 revision 覆盖管理员变更。
- 两端沿用每五秒刷新与页面隐藏暂停；共享 i18n 和 BigInt 字节格式，分别实际检查两种语言、桌面和窄屏。

## 升级、回退及限制

升级前备份完整 SQLite 数据卷。新版本迁移后旧程序会拒绝打开；回退必须同时恢复旧二进制和升级前完整数据。启动时先管理员初始化和配额周期推进，再恢复规则，防止短暂绕过。

既有管理员凭据及无套餐规则保留，根路径跳转到独立管理端。旧共享 API 路径不保留兼容别名，前端及脚本必须同步迁移；升级使原内存会话失效，重新在对应端登录。PORTER_TRAFFIC_FLUSH_INTERVAL 同时写入中英文 README 和 Compose 示例，清楚区分保存间隔、页面刷新与业务 UTC 时间。默认英文 README 是现有产品规范的例外，任务文档和注释保持中文。

限制与最终审核项：用户已接受强制退出可能丢未保存用量；实时断流仍有并发在途写入的技术边界；外部端口占用可能导致恢复失败；本期不提供编辑/删除套餐和用户、套餐切换、历史账单、支付或多节点。
