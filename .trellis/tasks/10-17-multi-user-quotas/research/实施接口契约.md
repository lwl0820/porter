# 实施接口契约

这是已批准设计的字段级补充，用于并行实施，修改需通知主会话和相关实现者。

## JSON

- Session：{user_id, username, role: admin|user, csrf_token}。
- User：{id, username, role, plan_id, port_start, port_end, created_at}；管理员的 plan_id 为 null，端口为 0；密码字段绝不输出。
- Plan：{id, name, port_count, traffic_limit_bytes: 十进制字符串, accounting_mode: both|max|upload|download, reset_mode: calendar_month|anniversary|fixed_day, reset_day: 整数或null, created_at}。
- Usage：{cycle_start, cycle_end, upload_bytes, download_bytes, used_bytes, limit_bytes, exceeded}；字节均为字符串，时间为UTC RFC3339。
- Account：{user: User, plan: Plan或null, usage: Usage或null}。
- Settings：{port_start, port_end, revision}；尚未配置时两个端口均为0，revision初始为1；PUT只接受1–65535有效范围。
- GET /api/admin/users → {users: Account[]}，仅普通用户；管理员本人来自当前Session，可用其ID作为规则归属和筛选。
- GET /api/admin/plans → {plans: Plan[]}；POST返回单个Plan。
- POST /api/admin/users输入{username,password,plan_id}，返回单个Account。
- GET /api/user/account → Account。
- 管理Rule为原有Rule扩展 owner_id 和 owner:{id,username,role}；普通用户Rule包含owner_id但不包含其他用户资料。
- 两端规则列表均为{rules: Rule[]}，管理端元素为带owner的Rule；新增和修改、重试及清零返回单条对应Rule。
- 管理端新增规则输入在原RuleInput外增加owner_id；用户端新增和双方更新的RuleInput不接受owner_id；更新不转移归属。
- Settings PUT输入{port_start,port_end}，携带If-Match；输出Settings与ETag。
- POST /api/admin/plans输入{name,port_count,traffic_limit_bytes,accounting_mode,reset_mode,reset_day}。
- 所有写入沿用Origin/CSRF，规则更新/删除/重试/统计重置沿用If-Match。

## 页面与会话

- /admin/、/admin/login；/user/、/user/login；/跳转/admin/。
- /api/admin/auth/login|session|logout；/api/user/auth/login|session|logout。
- Cookie分别porter_admin_session（Path=/api/admin）、porter_user_session（Path=/api/user）。
- 管理端/admin/rules；用户端/user/rules；后续完整路径以design.md为准，均在/api之下。
- 前端App拆为独立入口与根组件，可共用Rule列表和编辑器，不能共享单个全局csrf状态。
