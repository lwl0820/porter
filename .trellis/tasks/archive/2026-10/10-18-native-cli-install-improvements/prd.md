# 拆分服务与命令行并完善原生安装

## 目标与用户价值

将常驻服务与原生管理客户端拆为 porterd 和 porter，让 Docker 仅包含服务程序；原生用户一键安装后可通过系统 PATH 管理规则，安装器默认使用英文，CLI 首次选择并保存语言，后续启动复用。

## 背景与决策

- 用户已确认将本任务扩展为 porterd 服务端、porter 客户端拆分，连同安装器英文默认和 PATH 集成一起完成。
- 用户报告的管理员变量错误已确认为 v0.2.0 不含 CLI，官方发行包也已复现；不需要通过提供 Web 密码修复。
- 当前 cmd/porter/main.go 同时包含服务与 CLI；Docker 使用 porter_docker 标签禁用规则管理，而非独立服务入口。发行包只含一个 porter，旧 unit 直接启动它。
- 源码位置、旧版复现与 PATH 依据见 research/安装与版本证据.md；新增拆分证据见 research/双程序拆分证据.md。

## 需求

### R1：安装器英文默认

- 未指定 --lang 时显示 1 English、2 中文，回车/1/en 选择英文，2/zh-CN 选择中文。
- 显式 --lang en/zh-CN 跳过选择，参数位置兼容；无终端帮助和参数错误默认英文。
- 安装、升级、卸载、帮助及自有错误均支持双语；外部命令诊断不翻译。首次凭据与卸载确认仍要求终端。
- CLI 的首次语言选择及持久化单独遵循 R7；安装器的语言选择不代替 CLI 首次设置。

### R2：独立服务与客户端

- porterd 常驻运行 Web、规则服务、转发、数据库及原生本机控制接口；porter 是独立短进程客户端，继续支持交互和参数式规则 CRUD。
- porter rules 与已有参数保持兼容；裸 porter 进入相同交互入口。porter --version、porterd --version 分别返回实际版本且不启动服务；版本查询沿用无需选择语言的例外。
- 客户端不加载 Web 管理员凭据、不打开 SQLite、不启动服务；服务入口不分流到 CLI，非法客户端参数在初始化配置前报错。
- 保留 root/sudo 管理员授权、Unix socket 对端校验、目录及节点权限、revision 冲突保护、服务不可用错误、取消/EOF/中断和 JSON 语义。
- 客户端构建依赖不包含规则服务、转发引擎、数据库、Web；服务构建依赖不包含 CLI 界面。共用模型/协议，不复制业务校验。

### R3：发布与 Docker

- 原生 amd64/arm64 发行包同时包含同版本 porter 和 porterd，保留既有归档名称与 SHA256SUMS 机制。
- Docker 仅构建及包含 porterd，镜像入口使用 /porterd；不包含 porter，且不创建默认或自定义本机控制 socket。
- 原生客户端放入容器后仍拒绝规则管理；Web、TCP/UDP、持久化、重启和正常退出保持既有行为。

### R4：原生安装及系统 PATH

- 默认 /opt/porter/porterd 和 /opt/porter/porter；自定义目录及空格、美元符、百分号继续支持。porter.service 名称、配置和数据位置保持。
- /usr/bin/porter 是指向实际客户端的托管绝对链接。若实际程序目录为 /usr/bin，使用已托管客户端本身，不创建自链接；不复制额外客户端、不修改 profile、PATH 或 sudoers。
- 新装创建入口；拆分版托管安装重跑补齐缺失托管链接并保持幂等，不下载升级、不重置程序、配置、数据库、账号或版本。
- 未知普通文件、目录、错误/未知/悬空链接均不得覆盖；管理归属可识别，原子创建且不强制覆盖。同目标未知手工链接也不能自动认领。
- 旧安装普通重跑仍保留原版本和单程序布局，明确报告旧布局/实际能力与显式迁移方法，不能伪装已获得独立客户端。

### R5：显式升级与旧安装迁移

- 新增 --upgrade，仅显式使用时下载目标版本；可配 --version 固定目标，不指定时选择最新正式 Release。普通重跑和单独 --version 不隐式升级。
- --upgrade 同时支持旧单程序迁移到双程序和已拆分实例的同布局升级；目标必须为已校验的双程序发行包，拒绝单程序目标和降级。同版本已完成实例幂等返回。
- 迁移前验证安装记录、版本、原 unit、账号、数据、所有目标资源及 PATH 冲突；下载或校验失败不得停止现有服务。
- 需要替换程序时停止服务，备份原程序、unit、安装状态、配置和完整数据目录，再切换双程序及 unit，检查版本、运行状态与健康后才提交完成记录。
- 失败恢复与备份匹配的旧程序、unit、状态和完整数据；中断可识别恢复，禁止半迁移状态以新版客户端充当旧服务。备份包含凭据，须限制权限。
- 升级/迁移会短暂中断转发，安装器在变更前显示目标和中断说明并要求确认；取消不修改服务、程序、入口或业务数据。

### R6：卸载与失败恢复

- 普通卸载及 purge 精确清理各自布局的托管程序、unit 和托管 PATH 入口；保留配置数据的卸载之后可恢复原版本、原布局及入口。
- 入口被替换或未知 unit 等冲突须在停止服务前拒绝；旧记录未管理的系统入口保留，不按同名粗暴删除。
- 继续保持两把安装锁、锁内状态重校、类型与路径校验、完整安装缺库拒绝及确认先于破坏性操作的保护。
- 不完整迁移优先恢复到可识别稳定布局，再允许升级/卸载；重试不能误删唯一备份。状态不可信则停止并给出恢复指引。

### R7：CLI 首次语言选择与持久化

- 用户新增要求：CLI 首次启动先选择语言、默认英文，选择后保存；后续无 --lang 启动默认使用已保存语言。本条替代此前“每次无 --lang 都先选择、空输入不默认”的合同。
- 使用独立系统配置 /etc/porter/cli.json 保存 language=en/zh-CN，不放业务数据库，也不与服务凭据环境文件或安装状态混存；root 与 sudo 共用该主机的 CLI 偏好。
- 无显式语言且无已保存设置时，交互第一步显示 1 English、2 中文，回车/1/en 为英文、2/zh-CN 为中文，确认后保存；取消、EOF、中断不保存，也不开始规则操作。
- 优先级为显式 --lang > 已保存语言 > 首次选择（默认英文）。--lang 仅覆盖本次，不改保存值，避免自动化脚本改变人工偏好；交互菜单提供切换语言并保存的入口。
- 无已保存语言且无控制终端时，给出英文诊断，要求 --lang，不写配置；存在已保存语言的参数命令可无人值守执行。--version 不触发语言选择或配置读写。
- CLI 偏好不依赖服务运行、socket 或 Web 密码；非root、容器及只读调用不创建系统配置。保存失败须明确告知未持久化，当前交互可使用已选语言继续，不宣称保存成功。
- 普通卸载保留 CLI 配置，恢复安装继续使用；--uninstall --purge 同时删除服务配置、CLI 配置、安装记录及既有彻底删除范围。新装/升级不得提前写入安装器选择的语言或覆盖已保存偏好。

## 范围外

用户/套餐管理、Web 页面和业务规则变化、远程 CLI、Docker 内规则 CLI、自动或后台升级、自动降级、用户 PATH/sudoers 修改、CLI 之外的语言偏好和数据库系统设置扩展，以及无关 Trellis 工具修复。数据库业务 schema 不因拆分改变；安装记录可独立演进。

## 风险与验证边界

- /usr/bin/porter 可能冲突，自定义 PATH 也可能不含 /usr/bin；拒绝未知资源且不修改用户配置。
- porterd 替代旧无参数 porter 启动方式，手工 unit/脚本须按文档修改；安装器仅迁移已验证的托管 unit。Docker 中硬编码 /porter 的外部命令也需切换。
- 显式升级增加停机及备份恢复路径，须验证故障矩阵，不能仅以正常升级成功作为验收。
- 临时文件与测试路径仅仓库 .tmp；真实 systemd 宿主、arm64 运行与模拟/交叉编译结果分别报告。
