# 默认用户登录与一键脚本双语卸载

## 目标与价值

默认打开 Porter 时进入普通用户登录入口，管理员继续通过独立地址访问；原生一键脚本支持中文和 English，并提供卸载能力。

## 已确认背景

- 用户已明确要求创建任务，确认卸载默认保留配置与数据库、另提供确认后的彻底删除选项，并明确批准最终方案；任务已进入实施。
- 生产根地址在 `web/embed.go:28` 重定向到 `/admin/`，现有断言位于 `web/embed_test.go:36`；开发根页面通过 `web/src/main.ts:1` 加载管理端。
- 管理端 `/admin/` 与用户端 `/user/` 已有独立构建入口、登录接口和会话隔离，无需新增登录系统。
- `scripts/install.sh:7` 的帮助、交互和错误均为中文；脚本目前支持安装目录、版本和帮助参数，尚无卸载分支。
- 脚本通过 `/etc/porter/install.json` 识别托管安装，配置位于 `/etc/porter/porter.env`，数据位于 `/var/lib/porter`，服务为 `porter.service`，程序默认位于 `/opt/porter/porter`，支持自定义目录。
- 安装成功输出目前仅给出管理端链接，见 `scripts/install.sh:341`。
- 前端已有中文和 English；内部会话、文档及注释使用中文，默认英文 README 保持现有例外。

## 需求

### R1 默认普通用户入口

- 生产环境与开发环境的根地址均进入普通用户端；未登录显示普通用户登录。
- 管理员仍可通过 `/admin/` 登录，两个入口保持各自导航、接口、Cookie 与 CSRF 状态。
- 安装完成提示分别标明用户与管理员访问地址，避免默认入口和部署说明冲突。

### R2 一键脚本双语

- 支持中文和 English，语言覆盖帮助、输入提示、校验错误、操作确认与结果。
- 保留 curl 管道执行、控制终端交互、隐藏密码、输入重试和既有安装保障。
- 未指定语言时，交互执行先提供中文和 English 选择，回车默认中文；允许通过语言参数直接指定。无控制终端时使用中文，帮助仍可直接查看。
- 安装和卸载均使用所选语言；系统工具自身的原始输出不承诺翻译。

### R3 卸载

- 同一脚本提供可发现的卸载入口，停止服务、取消开机启动并移除托管的 unit 与程序。
- 支持识别自定义程序目录；卸载不依赖下载新 Release，不重新询问安装凭据。
- 只操作能够确认属于本安装器的资源；失败返回非零，取消不删除文件。
- 默认保留配置、完整数据库目录、受限安装记录及专用服务账号，以便重装恢复；明确确认后才执行卸载。
- 彻底删除作为独立选项，额外提示将丢失账号、规则及统计，并要求再次确认；同时清理托管配置、数据、安装记录及专用账号和组。
- 保留数据后重新安装，复用原凭据、监听地址、规则及原安装版本，不误报为完整安装文件缺失，不隐式升级。
- 重复卸载给出已卸载提示；卸载中断后可重试，不先删掉用于识别托管资源的安装记录。

### R4 文档与验证

- 同步中英文 README 的默认入口、语言选择、卸载方式和数据处理说明。
- 增加根地址、独立入口、脚本双语和卸载回归验证；测试和临时产物放在仓库 `.tmp/` 内。

## 验收标准

- A1：访问 `/` 进入用户端，未登录时使用普通用户登录接口；显式访问 `/admin/` 仍正常工作，对应 R1。
- A2：两种脚本语言均可完成输入、查看帮助并理解失败原因，密码不回显，既有重复安装行为不回退，对应 R2。
- A3：卸载后服务停止且不再开机启动，托管程序和 unit 已移除，配置与数据库按最终确认策略处理，对应 R3。
- A4：取消、未知安装及卸载失败均不假报成功，不误删其他文件；验证自定义目录和重复卸载行为，对应 R3。
- A5：文档示例与实际行为一致，安装脚本回归和受影响的前后端质量检查通过，对应 R4。
- A6：默认卸载后重装保留原始配置和数据库内容，恢复同一版本；彻底删除必须经过额外确认，取消不开始卸载，对应 R3。

## 范围外

不增加用户注册、不合并双端会话、不改变角色权限、套餐与转发业务，不增加自动升级、Docker 卸载或 Docker 数据迁移，不配置防火墙及 HTTPS，不实际卸载用户服务器上的服务。
