# 入口与安装生命周期研究

## 已验证代码事实

- `web/embed.go` 仅对根地址返回跳转，双端深链接分别映射自己的构建页，未知资源与 API 保持 404；应修改跳转目标，不扩大前端兜底。
- `web/index.html` 载入 `src/main.ts`，后者导入 `admin.ts`；开发根页必须同步修改，否则只改 Go 处理器无法覆盖开发环境。
- `AdminApp.vue`、`UserApp.vue` 显式固定角色，底层 App 复用布局。修改根入口无需修改认证或角色判定。
- `scripts/install.sh` 从 `/dev/tty` 读取凭据，`collect_input` 最后关闭文件描述符 3；新增语言和卸载确认须协调描述符生命周期。
- 同脚本的 Python 辅助器严格解析 schema=1、目录、架构、版本及 initializing/complete 状态。`complete` 分支拒绝缺失程序、配置、unit、数据目录或数据库。
- 当前重试通过安装记录恢复既有版本和凭据；不能单纯删除程序而保留 complete 状态，否则下次安装必然被完整性检查拒绝。
- 当前安装锁分为程序目录锁和 `/etc/porter/.install-lock`，退出只应释放自己取得的锁；卸载应复用这一互斥边界。
- 安装记录和环境配置为权限 600；配置只经受限 Python 解析，不通过 shell source。卸载不得为了取得目录而执行记录或环境文件。
- `scripts/test-install.py` 已使用仓库 `.tmp` 内隔离目录、命令替身、模拟发布产物和伪终端；可以扩展测试而无需真实修改宿主 systemd。

## 当前需求对旧规范的明确变更

- 前端实际契约第 10.1 节中的“根地址跳管理端”改为“根地址跳用户端”。
- 后端原生安装契约扩展语言与卸载命令、卸载状态及保留数据重装，不删除既有 complete 安装缺失数据时的保护。
- 未选择彻底删除时保留专用账号/组，避免原数据库失去稳定所有者；彻底删除时先核验归属并停止服务，再删除资源。

## 验证边界

这是本地源码与现有规格研究，未联网查询 Release 是否存在，未实际安装或卸载宿主资源。既有归档任务中记录的历史 Release 可用性不应被当作本轮实时查询结果。
