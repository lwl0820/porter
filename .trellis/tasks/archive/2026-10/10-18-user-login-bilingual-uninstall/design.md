# 技术设计

## 变更边界

行为差距有两处：根地址目前选择管理端；原生安装器仅提供中文安装流程。分别在已有静态资源入口与安装器内修正，不在登录组件增加角色推断。

同一任务统一验收入口、安装输出、双语与卸载恢复，避免入口地址和脚本文档各自交付造成不一致；不额外建立父子任务。

预计修改文件：

- `web/embed.go`、`web/embed_test.go`：生产根地址重定向至 `/user/`，验证 GET/HEAD、双端深链接及 API 404。
- `web/src/main.ts`：开发根页加载现有用户端入口；显式管理员入口不变。
- `scripts/install.sh`：消息集中、语言选择、卸载分支、安装状态与卸载后恢复。
- `scripts/test-install.py`：扩展现有命令替身与伪终端测试，覆盖双语及卸载状态转换。
- `README.md`、`README.zh-CN.md`：同步入口、参数、确认交互和数据处理。
- `.trellis/spec/frontend/contracts.md`、`.trellis/spec/backend/contracts.md`：完成后更新默认入口、原生脚本和恢复契约。

不修改认证接口、Cookie、CSRF、用户权限、套餐或转发实现；不增加前端开发需求提示或新页面。除非现有 CI 不能覆盖新增行为，否则不改发布与 CI 工作流。

## 默认入口

生产 `/` 保持现有 302 语义，目标改为 `/user/`。开发根页的 `main.ts` 改为引用 `user.ts`；`/admin/` 和 `/user/` 继续加载固定角色根组件。App 的既有角色默认值不作为根入口修复点，避免扩大到原有测试与内部挂载调用。

安装就绪提示同时输出明确标注的用户地址和管理地址。默认打开普通用户入口不会自动创建普通用户；继续由管理员添加账号。

## 脚本命令与双语

保留现有默认安装命令，增加：

```bash
bash scripts/install.sh --lang zh-CN
bash scripts/install.sh --lang en
bash scripts/install.sh --uninstall
bash scripts/install.sh --uninstall --purge
```

- `--lang` 接受 `zh-CN` 与 `en`。参数先完成语言识别，再输出帮助或校验错误，参数位置不改变语言。
- 未指定语言且有控制终端时，显示双语语言选项，回车默认中文；无终端时默认中文。帮助仅输出所选语言的说明，不要求权限、终端或宿主检测。
- 默认命令继续安装；`--uninstall` 明确切换操作，避免破坏原有重复运行语义。卸载入口和彻底删除选项在帮助中清晰列出，不强制增加操作菜单。
- `--purge` 仅与 `--uninstall` 搭配；卸载不接受 `--version`。`--install-dir` 可用于核对记录目录，未传入时从托管安装记录识别自定义目录。
- 产品消息由脚本内集中消息函数维护，使用稳定键及 printf 参数；新增消息必须同时提供两种语言。内部注释使用中文。外部命令诊断可保留原始输出，脚本自有错误须使用所选语言并返回非零。
- 语言、凭据和确认均从 `/dev/tty` 读取，不能读取 curl 脚本管道；不要在选择语言后提前关闭后续交互需要的终端描述符。

## 卸载与资源归属

卸载不请求 GitHub、不下载程序、不安装软件包，也不重新采集管理员凭据；使用现有 Python 标准库读取托管记录，缺失依赖时给出明确错误。

1. 校验参数、宿主、权限和托管安装记录。识别记录内程序目录并执行原有路径约束，拒绝符号链接、目录冲突和显式目录不匹配。
2. 检查安装目录锁与全局锁；只释放本进程成功获取的锁。核对实际 FragmentPath、存在的 unit 与原安装器模板，以及专用账号 home、主组和禁止登录 shell；未知资源拒绝处理。
3. 列出将删除和保留的资源，要求明确确认，默认取消。彻底删除再要求输入指定确认词；所有确认均在开始修改状态、停服务或删文件前完成。
4. 原子记录卸载中状态，停止服务并取消开机启动，确认服务不再活跃。服务控制失败时停止，保留文件及状态以便重试；不可用 `|| true` 掩盖真实失败。
5. 删除确认归属的 unit 和程序，执行 daemon-reload。程序目录仅在空目录时尝试移除，绝不递归删除用户自定义目录或其额外文件。
6. 默认卸载保留完整数据目录、配置、安装记录与专用账号/组，记录已卸载状态并输出重装方法。
7. 彻底删除在已停服且归属核对成功后清理固定配置与完整数据目录，删除核验后的专用账号/组；安装记录最后移除。配置目录若有额外文件应保留这些文件。操作失败保留足以重试的状态，不报告成功。

已无托管记录时：若发现同名服务、配置、程序、数据或账号等资源则拒绝推断归属；仅在相关资源均不存在时把重复卸载视为成功的空操作。不删除软件包、防火墙规则、Docker 资源或 systemd 的共享日志。

## 状态与恢复

沿用 schema=1，保留 `directory`、`arch`、`version` 字段，为 `status` 增加 `uninstalling` 与 `uninstalled`。旧 `initializing`、`complete` 记录继续接受。

| 状态 | 安装行为 | 卸载行为 |
| --- | --- | --- |
| initializing | 沿用已有局部安装恢复，不重置凭据 | 校验已存在的托管资源后卸载 |
| complete | 保持现有文件完整性检查，不把文件丢失自动修复为空库 | 完整卸载 |
| uninstalling | 拒绝安装，提示先重试卸载 | 容忍本次卸载已删除的托管文件，继续剩余步骤 |
| uninstalled | 要求原配置与数据库仍在，下载记录版本并恢复程序和 unit | 默认卸载提示已完成；彻底删除仍要求确认 |

保留数据重装明确复用原版本，仍需 SHA256SUMS 校验。若历史版本不再可下载则报错，保留原配置和数据，不静默选择新版本。旧脚本无法识别新增状态，README 提示使用更新后的脚本恢复；回退脚本代码不会恢复已删除的服务和程序。

## 验证与限制

扩展现有模拟安装器测试，利用独立目录内命令替身观察服务控制、资源删除与失败次序；不在开发机实际创建或卸载系统服务及账号。使用伪终端验证两种语言、取消和额外确认；继续检查隐藏密码、终端恢复、校验和、锁及重复安装。

验证普通卸载后完整配置/数据库字节内容不变、同版本重装恢复、彻底删除和中断重试。生产构建后检查嵌入资源及独立双端，浏览器检查开发与生产根入口。模拟结果不等于在全部目标发行版真实 systemd 宿主完成实测。
