# 中英文双语技术设计

## 模块与数据流

在 `web/src/` 建立轻量国际化模块，利用现有 Vue 响应式能力共享语言偏好，不新增状态框架或国际化依赖。中英文词条集中维护，键集合通过 TypeScript 约束，动态数量和名称使用参数插值，避免中文语序直接拼接成英文。

语言状态启动时读取独立 localStorage 偏好键；缺失、非法或访问异常默认 `zh-CN`。设置时立即更新响应式状态，再尝试写入存储；存储写入失败只影响记忆，不阻止页面使用。同步 `html.lang`、title 和 description。组件只消费统一翻译入口，禁止遍历 DOM 替换文案。

增加复用语言切换组件，在启动/登录/管理页面合适位置展示。使用原生选择控件或等效可访问按钮，选项固定为“中文”和“English”，使用户误选后仍能识别切换入口。布局沿用当前样式，窄屏不隐藏语言入口。

## 文案与错误边界

App、规则编辑器、操作按钮、流量组件全部使用词条。协议 label、icon、className 仍由协议元数据统一维护，描述与状态标签在展示时动态翻译，不缓存为模块初始化时的字符串。

持久显示的错误、通知和校验保存可重新翻译的描述或键；服务端失败保留 code、status、fields 和原始信息，在显示时解析为本地化文本。api.ts 继续作为唯一 fetch 与响应校验边界，不向组件泄露未经校验的数据。

已知服务端 code 优先映射（含认证、CSRF、表单、监听冲突、revision、数据库等）。字段根据已知字段与原因映射，端口、IP、目标单播等约束不混用。监听失败按 `last_error_code` 和当前后端有限的协议模板映射，保留 TCP/UDP/TCP+UDP 的诊断意义。未知失败采用所选语言的通用提示，不依赖不受控字符串强行机器翻译；中文已知服务端说明保持原有信息量。

## 兼容与取舍

不修改 API 载荷、后端业务逻辑或存储结构。不把语言偏好混入认证数据；Cookie 和 CSRF 继续遵循原契约。保留协议筛选、请求版本、BigInt 字节格式化以及异步操作防重。

默认中文延续当前行为；本次不增加自动判断浏览器语言，避免首次访问与当前默认不同。两种固定语言采用小型词典，未来语言或复数复杂度显著增加时再评估专门依赖。

## 风险与回退

主要风险为英文扩展造成窄屏溢出、已显示错误不能响应切换、中文测试间受全局语言污染。通过浏览器检查、运行时切换错误测试和每例重置语言偏好控制。回退可整体撤销本任务前端改动，无数据库迁移；遗留偏好键对旧版无影响。
