## 实施顺序

1. 由 trellis-implement 子代理负责 `web/` 国际化模块、词典、语言切换组件、文案替换、错误展示与相关测试。实现前使用 trellis-before-dev，并按需通过 Context7 核对 Vue API。不改后端，不覆盖其他人的未提交文件。
2. 共享响应式语言、存储降级、文档元信息以及消息描述机制；迁移 App、RuleEditor、RuleActions、RuleTraffic、types 和 api 中的展示文案。
3. 增加行为回归：默认中文、切换与持久化、已有错误切换、英文表单与 API 失败、用户输入保留。维护原有中文业务用例的隔离。
4. 由 trellis-check 子代理复核全部改动并执行适当自修复；主会话检查集成与真实浏览器桌面、窄屏中英文流程。
5. 主会话更新国际化规范，完成必要质量检查和最终差异审阅，按项目流程提交并收尾。

## 验证命令

所有临时输出与缓存使用 `.tmp/`。依赖存在时不重复安装。

- `npm --prefix web run lint`
- `npm --prefix web run type-check`
- `npm --prefix web run test`
- `npm --prefix web run build`
- 最后执行 `go build ./...`，与 web build 顺序执行，使用仓库 `.tmp/` 内 Go 缓存及临时目录。
- 实际浏览器检查启动/登录、管理页、编辑器、删除和重置确认；覆盖中文及 English、桌面及窄屏。

## 重点审查与回退

重点审查全局语言状态测试隔离、错误描述的响应式翻译、api.ts 的安全与载荷边界，以及窄屏按钮可访问性。业务语义不得借国际化改动调整。出现回归时仅撤销本任务相关改动，不回退仓库现有未提交配置。最终需求若产生实质变更则返回规划复审。
