# 前端增加中英文双语

## 目标

让中文与英文用户均可使用 Porter 前端，在页面内切换中文和 English，并记住选择。

## 背景与约束

用户要求“前端页面增加双语”，已同意按中文 / English 覆盖页面、表单、弹窗和提示并创建任务进入规划。当前 Vue + TypeScript 前端无国际化模块，文案散布于组件、类型元数据和 API 错误处理。现有规则管理、认证、轮询和流量统计行为必须保持。

会话、内部文档及注释使用中文；产品所需英文文案属于本任务范围。不得在产品页面展示开发需求、任务记录或验收过程。临时文件统一放仓库 `.tmp/`。

## 需求

- R1：启动状态、登录页及管理页均提供清晰可用的语言切换；语言为简体中文和 English。首次访问默认中文，手动选择优先，刷新或重新登录后保持浏览器内的选择。存储不可用或值无效时正常显示中文，仍可在当前页面切换。
- R2：翻译页面文案、状态、协议说明、按钮、占位符、工具提示、无障碍标签、空态、计数、时间相关展示和页面标题；同步页面语言属性。
- R3：表单校验、登录失败、网络异常、冲突、版本过期、会话过期、监听失败、删除与重置等已知产品错误和反馈采用当前语言。语言切换时已经显示的提示也随之更新，不丢失用户输入或清除错误。
- R4：规则名称、主机、账号、协议标识、字节单位等数据保持原值；切换语言不刷新页面、不提交请求、不影响表单和转发状态。
- R5：桌面和窄屏均可使用语言切换，英文较长文案不遮挡关键操作；保留现有弹窗焦点及防重复提交行为。

## 验收标准

- A1（R1）：无偏好时中文；切换 English 后立即更新，刷新后保持，登录态改变不重置选择；存储异常不使页面崩溃。
- A2（R2、R3）：登录、搜索筛选、新增与编辑、启停重试、删除、流量重置的页面和提示支持两种语言；已显示的校验、API 错误及通知切换后更新。
- A3（R4）：切换时表单数据、规则名和当前列表不变，不触发写请求；CSRF、If-Match、轮询竞争处理及协议筛选保持现有语义。
- A4（R5）：实际浏览器检查中英文桌面及窄屏、编辑器和确认弹窗，按钮有正确可访问名称。
- A5：前端 lint、type-check、test、build 通过；最终产物 Go 构建通过；新增用例覆盖切换、持久化、英文校验及错误映射。

## 不在范围内

额外语言、浏览器语言自动推断、后端接口多语言协议、翻译用户数据、README 全面重写，以及其他业务功能或视觉重构。

用户已审阅最终方案并明确同意实施，任务进入执行阶段。
