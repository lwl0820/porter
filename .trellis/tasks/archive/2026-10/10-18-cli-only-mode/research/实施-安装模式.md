# 可选管理入口安装器实施与验证

## 改动边界

负责 `scripts/install.sh`、`scripts/test-install.py`，不修改服务端、CLI、README、规范或 Git 提交。复用既有嵌入 Python 辅助器及持久升级事务；新增组件状态与切换而非另一套恢复机制。临时副本、日志及测试目录均位于项目 `.tmp`。

## 已实现行为

- 首次安装先选语言，再逐项选择 Web/CLI，默认双开，双否重选。CLI-only 不输入、生成或要求 Web 凭据/地址。Web-only 只部署 porterd，不创建托管客户端和 PATH 链接，也不接管无关系统 porter 命令。
- schema3 固定 split，严格 `features:{web:bool,cli:bool}`，至少一项；与 env 明确的 `PORTER_WEB_ENABLED`/`PORTER_CLI_ENABLED` 一致。schema1/2 的原版本恢复不强制新能力。旧 legacy 升级后保留 Web-only；旧 split 升级后保留双入口。
- 普通重跑默认不修改组件，可显式切换全部六个方向。开启 CLI 只取记录同版本包；关闭保留 CLI 语言。已有合法 Web 配置复用；首次开启收集凭据。无变更不重复停服、启动、启用或 daemon-reload，原停止/禁用意图保留。
- 候选程序通过 `--help` 的 `--check-config` 能力及受限环境预检；密码不进入 argv、命令日志或诊断。真实帮助输出到 stderr 的跨层问题由独立检查发现并修复，fixture 已增加对应回归。
- Web 就绪验证实际地址 healthz；CLI 用 root Unix HTTP `GET /v1/rules` 验证 JSON，避免语言向导；双入口两者均验证。Web-only 检查不存在本机控制入口。
- `upgrade/reconfigure` 共用受限 ID、阶段及完整备份、数据整体恢复；记录原/目标 features，保留 owner/mode/精确状态字节和 active/enabled 意图。兼容旧六键 transaction，恢复时内存规范化，不改旧 install.json 快照。
- CLI-only 开启 Web 在确认前及双锁内检查启用 TCP/组合监听冲突；活跃源优先 Unix API，停止源对固定库使用正确 URI 编码、`mode=ro`、`query_only`、固定 SELECT。停服确认后、备份和替换前再读库检查，消除 API 预检到 stop 之间并发创建规则的窗口；竞态冲突按 stopped 阶段恢复原服务，保留刚新增规则。地址匹配与服务端一致，IPv4-mapped 归一后同族，相等或任一通配即重叠。
- 卸载、重装、升级、purge 按模式精确处理程序与入口，正式配置/数据和历史备份的原保留边界不变。

## 范围与限制

安装测试使用真实伪终端、真实文件权限/目录/链接/SQLite、校验发行包和命令替身，不操作宿主账号、真实 systemd 或业务数据。本报告不把替身 systemd 当作真实宿主部署，也不把 fixture 程序当作真实服务/转发。真实原生模式、root/nonroot 授权和转发由服务实施/集成报告与独立检查另行覆盖。最终提交和发布由主会话处理。
