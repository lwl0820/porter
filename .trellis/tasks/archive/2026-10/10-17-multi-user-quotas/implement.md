# 实施计划：多用户、套餐及配额

## 启动条件

- 用户已明确回复“是”，批准当前修订版完整规划；允许启动任务并按以下计划实施。
- 用户批准最终摘要后，核对 PRD、设计和上下文清单仍与批准版本一致，再执行 task.py start。
- 本需求为一个跨层集成功能，按以下依赖顺序推进，统一验收；无单独先上线的子任务。
- 当前工作区含既有未跟踪 Trellis、平台和其他任务文件；不得清理、覆盖或混入本任务提交。

## 执行方式

实施和检查使用 trellis-implement、trellis-check 子代理，主会话负责协调、需求确认、规格更新及收尾。每次派发以 Active task: .trellis/tasks/10-17-multi-user-quotas 开始，明确文件所有权，并告知其他代理可能同时工作，不得回退他人修改。

数据库、认证、服务和转发之间存在紧密依赖，先以同一实现代理串行推进后端；契约稳定后前端可独立推进，但不能同时修改共享契约。所有代理先按仓库规范加载上下文，主会话不绕过规划门禁。

## 关键验证矩阵

| 场景 | 必须证明 |
| --- | --- |
| 权限 | 两用户隔离、两端 API 和会话隔离，直接请求不能越权，管理员可直接操作用户规则但不能绕过端口和额度。 |
| 管理列表 | 默认全部及所属用户准确；按 ID 筛选含管理员本人，与其他条件组合正确；旧请求不能覆盖新筛选。 |
| 独立后台 | 入口、登录、导航和请求前缀独立；双端 Cookie/CSRF 及登出不串用；深链接刷新可用，旧共享 API 无业务数据。 |
| 分配 | 并发只分配一次、连续段耗尽或碎片时回滚；管理员端口、管理端口、存量分配都排除。 |
| 模式 | U+D、max(U,D)、U、D 公式正确；两个规则方向相反时 max 对全用户聚合。 |
| 断流 | 实际 TCP/UDP/组合跨规则耗尽后主动断开，无需 GET；其他用户持续传输，保存间隔加长不拖延断流。 |
| 周期 | UTC 月末与闰年、31 日回锚、首次开户、精确边界、跨周期重启与旧通知竞争。 |
| 恢复 | 仅恢复仍启用规则，主动停用/删除保持；监听失败孤立，周期事务失败不发放新额度。 |
| 保存 | 默认与可配置间隔、非法值、保存失败保留增量、旧周期快照不覆盖、正常退出及最终保存错误。 |
| 展示统计 | 开关和清零仍按原有约定工作，不影响用户账本；规则删除不退款。 |
| 兼容 | 旧库无损、原管理员凭据可登录、旧规则恢复；管理员改名冲突不误接管用户。 |
| 界面 | 两种语言、窄屏、四种计费和三种周期表单、UTC、配额暂停与停用区分、旧请求及跨账号清理。 |

## 验证命令

所有目录、缓存、临时文件必须在仓库内，使用任务专用变量，不访问系统临时目录：

```bash
mkdir -p .tmp/tmp .tmp/go-cache .tmp/go-path .tmp/go-mod .tmp/npm-cache
export TMPDIR="$PWD/.tmp/tmp" GOTMPDIR="$PWD/.tmp/tmp"
export GOCACHE="$PWD/.tmp/go-cache" GOPATH="$PWD/.tmp/go-path" GOMODCACHE="$PWD/.tmp/go-mod"
export npm_config_cache="$PWD/.tmp/npm-cache"
npm --prefix web run lint
npm --prefix web run type-check
npm --prefix web run test
npm --prefix web run build
go vet ./...
go test -race ./...
go test -count=1 ./tests/integration/...
CGO_ENABLED=0 go build -trimpath -o .tmp/porter ./cmd/porter
docker build -t porter:local .
python3 scripts/docker-smoke.py porter:local
```

先完成前端 build 再运行 Go 检查，确保嵌入资源存在。依赖安装仅在缺失时执行，使用现有锁文件和仓库缓存。Docker 若不可用，明确记录未验证，不能把编译或模拟结果冒充容器实测。

## 高风险位置与回退

- internal/store/migrations 与 store.go：迁移、外键及旧数据；回退需旧二进制和升级前完整数据卷。
- internal/rules/service.go、runtime_group.go、traffic.go：共享锁、监听预备、配置提交、周期转换及保存顺序。
- internal/forward/tcp.go、udp.go、engine.go：持续流量计数、信号与 Stop 等待，必须用真实连接和 race 检查。
- internal/auth/auth.go、httpapi/server.go：两端会话与 Cookie/CSRF、路由域、凭据边界、角色及越权枚举；旧接口不能遗漏。
- web/src/api.ts、types.ts、两端入口及根组件、web/vite.config.ts、web/embed.go：独立请求客户端、归属显示与筛选竞态、构建资源和深链接、状态枚举及双语。

实施期间若改变功能范围、计费规则、端口独占、周期或异常退出容错，应回到规划并重新审核；不允许代理自行更改已确认业务语义。
