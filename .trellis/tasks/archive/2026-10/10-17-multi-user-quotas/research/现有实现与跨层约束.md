# 现有实现与跨层约束

## 认证与用户归属

- `internal/auth/auth.go`：只有单一管理员凭据和内存会话；多用户需增加持久化用户、密码派生结果、角色及稳定用户标识，不能复用当前单密码摘要实现来存储普通用户密码。
- `internal/httpapi/server.go`：所有规则接口目前只校验登录、Origin 和 CSRF。新增归属校验必须覆盖列表、保存、删除、重试和规则统计重置；普通用户归属由服务端会话决定。管理端的独立创建输入可指定所属账号，但必须验证管理员角色及目标账号存在，其他更新不接受归属转移。
- `internal/model/rule.go`：规则没有归属字段；迁移需为既有规则补齐稳定管理员归属，保留原 ID、revision、启用状态和累计量。

## 端口分配与现有冲突约束

- `internal/rules/service.go` 的 `validate` 已校验 1–65535、管理监听冲突、协议交集及同地址族的通配监听重叠；新端口范围校验必须在此基础上叠加，不能替代原有真实监听校验。
- 当前停用规则也参与配置冲突检查；分配用户范围时应考虑原有管理员规则和管理端口，避免给出无法兑现的可用端口。
- `internal/store/store.go`：SQLite 外键开启、单连接、进程排他文件锁；用户创建和范围分配适合在同一事务内执行。并发创建仍需数据库约束和串行分配保护。
- 外部进程占用端口会变化，分配范围不能承诺操作系统端口始终可监听；实际添加和恢复规则时仍须处理监听失败。

## 配额与展示统计必须独立

- `internal/forward/traffic.go` 的 `Traffic.Add` 在统计关闭时直接返回，`rules.Service.ResetTraffic` 可清空展示累计，删除规则会级联清理 `rule_traffic`；这些累计不能直接承担用户额度账本。
- 当前成功写出的应用载荷按上下行累计，TCP 每次写出计量，UDP 在写出后计量；组合规则共享展示统计。
- 用户配额需要跨全部规则、协议及连接共享对象；超额通知必须交给独立协调过程关闭整个用户的运行组，不能从转发协程里同步停止并等待自身。
- 套餐支持双向 U+D、单向 max(U,D)、只上行 U、只下行 D。配额账本必须独立保存本周期用户级累计 U 和 D；不能仅保存一个每次写入都增加的计费累计值，否则单向模式会计算错误。
- 用户级共享对象按本周期汇总后计算用量，不按单条规则取较大值。需对 U+D 做溢出保护，并在 API 中以十进制字符串传递累计字节，保留现有浏览器整数精度约束。
- `internal/rules/runtime_group.go` 已有监听故障只发信号、服务协调关闭的模式；配额停转发可沿用这种生命周期边界。
- 达到限额和周期重置要使用用户及周期标识隔离旧通知，防止上一周期的超额通知停止下一周期已恢复的规则。

## 周期与恢复

- 用户已确认三个套餐级重置方式、短月份取月末且保留原始日、UTC 00:00 重置，以及恢复原本启用的规则。
- 用户已接受异常退出可能丢失尚未保存的用量，并要求保存间隔可通过环境变量配置；设计采用 PORTER_TRAFFIC_FLUSH_INTERVAL，默认 5s，覆盖用户配额与规则展示累计的保存，但不改变实时超额判断、UTC 周期和页面刷新。
- 开户日期模式不能反复对上一次月末结果加一个月，否则会永久漂移。每次从原始开户日计算目标月份，并将日期截取到当月最后一天。
- `rules.New` 当前启动即恢复 enabled 规则；新流程必须先加载用户配额并推进过期周期，再决定是否准备监听。
- 超额运行状态应与规则 `enabled` 意图分开，配额停止不能把全部规则写成用户主动停用。
- 停机跨多个周期只需恢复当前周期，不应重复清零或累积未使用额度；首次开户完整额度、未用额度不结转等语义已纳入最终方案审核。

## 验证范围与实施边界

- 核心验证：角色隔离、越权规则 ID、并发端口分配、UTC 日期边界、月末及闰年、跨规则真实 TCP/UDP 消耗、超额主动断流、重置恢复、重启与持久化故障。
- 沿用项目现有前后端质量门禁；所有缓存、测试临时文件及工具输出仅放在仓库 `.tmp/`。
- 新功能页面保持中英文切换和窄屏交互；账号、套餐名称等用户输入不翻译，页面不展示内部任务文案。
- 当前只进行了需求和代码调研，尚未修改产品代码。

## 最新要求：独立双端与管理员规则管理

- 用户要求管理端显示所有用户规则、每条所属账号、按用户筛选，并可直接执行所有规则操作；页面和接口均须与用户端独立。
- 当前 web/src/main.ts 只挂载一个 App.vue，api.ts 只有单个全局 csrf 和 unauthorized 回调。不能仅增加 role 条件继续复用同一会话状态；应拆独立应用入口并实例化固定前缀客户端，底层组件和解码逻辑仍可共用。
- 当前 HTTP 仅有共享 /api/auth/*、/api/rules*，单一 porter_session Cookie。新方案改为 /api/admin/*、/api/user/*，Cookie 名及 API Path、服务端会话所属端和前端 CSRF 同步隔离。
- web/embed.go 当前直接使用 FileServer，不能自动处理 /admin/login 或 /user/login；需要明确的双端首页映射，并保留 API 的结构化错误而非返回 HTML。
- 管理列表需要权威 owner 数据和 owner_id 过滤，普通用户接口强制本人范围，不提供跨账号过滤或赋值。测试除两个普通用户，还须包含管理员自身规则，防止遗漏本人所属信息或筛选选项。
- 旧共享 API 不能保留可绕过端隔离的入口，已有 API 测试、集成脚本和文档必须同步迁移。上述内容已写入修订版规划，尚未实施。
