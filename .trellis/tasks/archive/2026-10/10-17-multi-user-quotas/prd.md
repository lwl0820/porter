# 多用户、套餐与端口及流量配额管理

## 目标与用户价值

管理员通过独立管理后台统一管理全部用户规则，并通过套餐分配用户端口和流量；普通用户通过独立用户后台管理自己的规则，不能越权使用端口，套餐流量用完后停止该用户所有转发，新周期自动恢复。

## 背景与现有事实

- 当前只有环境变量配置的单一管理员，内存会话不包含用户标识或角色：`internal/auth/auth.go:12`、`internal/auth/auth.go:30`。
- 现有规则无用户归属字段：`internal/model/rule.go:45`；规则接口统一要求登录，但不区分角色或用户：`internal/httpapi/server.go:39`。
- 规则统计关闭后不计数：`internal/forward/traffic.go:47`；展示累计可手动重置：`internal/rules/traffic.go:60`；删除规则会移除统计：`internal/rules/service.go:265`。因此不能直接用规则展示累计作为套餐额度账本。
- 统计每秒采样、每五秒保存：`internal/rules/traffic.go:10`；启动直接恢复已启用规则：`internal/rules/service.go:80`。新需求须覆盖数据路径、后台持久化和启动恢复。
- 现有产品界面支持中文和 English；会话、内部文档、代码注释使用中文，临时文件仅存放在仓库 `.tmp/`。

## 功能需求

| 编号 | 要求 |
| --- | --- |
| R1 | 增加多用户和管理员、普通用户角色；普通用户仅能管理自己的规则，服务端校验权限。 |
| R2 | 管理员可添加和查看套餐，设置名称、端口数量、流量额度、流量计费方式和重置方式。 |
| R3 | 管理员可添加和查看用户，创建时填写账号、密码并选择套餐，成功后展示分配结果。 |
| R4 | 增加系统配置，管理员可设置用于分配用户端口的起止范围；未配置前不允许创建普通用户。 |
| R5 | 创建用户时从配置范围内按套餐数量分配端口；端口不足时整体失败，不留下半成品账号或占用。 |
| R6 | 普通用户新增、编辑、启用和重试规则均须遵守分配的监听端口范围，直接接口请求同样受限；目标服务端口不受此范围限制。 |
| R7 | 用户全部规则共同消耗套餐额度，达到额度后停止该用户全部转发并断开已有会话；正常启用、重试和重启均不能绕过，其他用户不受影响。 |
| R8 | 用户配额独立于可选的规则展示统计；关闭或清空展示统计、修改或删除规则不能返还已消耗额度。 |
| R9 | 套餐可选自然月重置、按开户日期每月重置、固定某天重置；用户采用所属套餐的重置配置。 |
| R10 | 固定重置日或开户日为 29、30、31 日且当月不存在该日期时，在当月最后一天重置；后续月份仍依据原始日期计算。 |
| R11 | 新周期自动恢复仅因额度耗尽而停止、且当前仍设置为启用的规则；手动停用和已删除规则不恢复。 |
| R12 | 三种重置方式统一按 UTC，在重置日 00:00 开始新周期；开户日按创建时间的 UTC 日期确定，不使用服务器或浏览器本地时区。 |
| R13 | 每位用户独占连续数字端口段，长度等于套餐端口数量；TCP、UDP 和不同监听地址共用该范围，其他用户不得分配相同数字端口。 |
| R14 | 修改系统分配范围只影响后续创建的用户，已有用户端口和规则不迁移、不中断；已有分配仍作为占用，防止新分配与其重叠。 |
| R15 | 套餐可选双向、单向、只计上行、只计下行；按用户当前周期全部规则汇总后的上下行计算，不逐规则、连接或采样取较大值再求和。 |
| R16 | 用户接受异常退出时丢失最近尚未保存的用量；流量保存间隔通过环境变量配置，默认五秒。正常退出最终保存；运行时断流不等待保存定时器。 |
| R17 | 升级保留环境变量管理员登录方式，既有规则归该管理员，保持原 ID、revision、时间、配置、启停及展示累计。管理员自有规则不受普通用户套餐限制，但不能新占用已分配给用户的数字端口。 |
| R18 | 普通用户可查看自身套餐、端口范围、本周期上下行、计费用量、额度、额度状态及下次重置时间。 |
| R19 | 管理员规则列表默认显示包括管理员自身在内的全部用户规则，每条显示所属账号；支持按用户筛选，并可与原有名称/地址搜索、协议和状态筛选组合。筛选以稳定用户 ID 为准，由管理接口执行。 |
| R20 | 管理后台和用户后台具有独立页面入口、登录、导航、会话状态及 API 命名空间；同一服务部署下分别使用 /admin/、/user/ 页面和 /api/admin/*、/api/user/* 接口，不能只在同一界面隐藏按钮实现角色区分。 |
| R21 | 管理员可通过管理端直接操作任意用户的规则，包括为所选账号新增、编辑、删除、启停、重试和重置展示统计；不必登录为该用户。操作普通用户规则时仍遵守所属用户的端口和额度限制，修改规则不转移归属。 |

## 套餐流量计费规则

上行 U 指客户端到目标服务的成功转发应用载荷，下行 D 指目标服务到客户端的成功转发应用载荷，不计协议头、握手和 TCP 重传。U、D 是本用户当前周期的累计值，与展示统计独立。

| 套餐选项 | 计费用量 |
| --- | --- |
| 双向 | U + D |
| 单向 | max(U, D) |
| 只计上行 | U |
| 只计下行 | D |

例如两条规则分别上传 100、10 字节，下载 10、100 字节，单向为 110 字节，双向为 220 字节。只计单侧时另一方向仍保留累计供展示，但不消耗额度；任何模式额度耗尽均停止双向和所有规则。

## 周期规则

- 自然月：UTC 每月 1 日 00:00 重置。
- 按开户日期：以开户的 UTC 日号为锚点，每月该日 00:00 重置。
- 固定日：套餐指定 1–31 日，每月该日 UTC 00:00 重置。
- 短月份取当月最后一天。例如锚点 31 日，平年二月在 28 日重置，三月恢复在 31 日。
- 首次开户即获得完整额度，持续到下一个重置点；未使用额度不结转。停机跨周期后直接进入当前周期，不重复发放多期额度。
- 周期重置只清零用户套餐计量，不清零规则展示累计。恢复监听失败按规则显示错误并允许重试，不阻塞其他规则。

## 兼容与运行约束

- 管理端和用户端使用不同登录会话和 CSRF 状态，可在同一浏览器同时登录；任一端退出不注销另一端。角色不匹配的登录和接口访问必须被服务端拒绝。
- 旧共享 `/api/auth/*`、`/api/rules*` 路径不继续提供业务接口，升级后前端和自动化脚本切换到对应端的独立路径；根地址 `/` 跳转到管理端，保留原管理员访问习惯。
- 拟新增 `PORTER_TRAFFIC_FLUSH_INTERVAL`，默认 `5s`，用于套餐用量与规则展示累计的保存。它不改变每秒速度采样、前端每五秒刷新和 UTC 周期边界。
- 保存正常时异常退出可能丢失一个保存间隔内的增量；持续存储失败会扩大该窗口，必须保留内存数据、记录错误并重试，不能承诺异常断电零丢失。
- 既有管理员规则和管理端口参与数字端口分配排除。管理端口配置变化如与已分配数字端口冲突，应拒绝启动并报告冲突，不抢占用户资源。
- 外部程序占用端口仍可能导致监听失败，分配范围不等于提前占有系统 socket。默认不扫描或管理宿主机防火墙。
- 配额账本继续使用有界整数字节；API 输出精确十进制字符串，界面允许以 GiB 设置额度并清楚标注单位，避免浏览器浮点精度丢失。

## 范围边界

本期交付独立管理端和用户端、独立登录会话及接口、管理员全用户规则查看/所属账号/用户筛选/完整操作、用户与套餐的添加和查看、系统端口范围配置、普通用户规则隔离、端口约束、四种计费、三种周期重置、自动停转发与恢复、配置化保存间隔及旧数据兼容。

暂不包含独立服务或域名部署、旧共享 API 兼容别名、规则归属转移、自助注册、支付、自动续费、未用流量结转、历史账单、多节点和异常断电零丢失。套餐编辑与删除、已有用户套餐切换、用户编辑/禁用/删除及密码重置未被请求，本期不扩展；这些边界纳入最终方案审核。
