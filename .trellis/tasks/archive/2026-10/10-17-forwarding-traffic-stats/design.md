# 转发流量统计技术设计

## 状态与边界

用户已批准本设计，任务已启动实现。作为一个跨层功能整体交付，不拆分为独立子任务，避免接口、运行态和持久化各自完成却无法验收。

规则配置仍由规则服务管理；转发层只负责成功载荷字节计数；统计采样、持久化、重置由服务协调；HTTP 层仅处理鉴权、请求校验与响应；前端使用统一接口解码器。

## 数据流与模型

1. 启动时读取规则配置和累计统计，以规则 ID 创建共享统计对象，再恢复监听。
2. 同一逻辑规则的 TCP、UDP、替换中的运行实例和已有会话引用同一统计对象；统计生命周期独立于监听器、generation 和预算引用。
3. TCP 每次写入和 UDP 每次发送后，仅累计成功写出的字节；客户端到目标计上行，目标到客户端计下行，失败或丢弃部分不计数。
4. 服务每秒按单调时间和字节增量计算速度，每 5 秒批量落盘有变化的累计值。GET 只读取快照，不推进采样基线。
5. 前端沿用每 5 秒列表刷新、隐藏暂停和刷新失败保留旧数据的行为。

建议新增 `internal/forward/traffic.go` 承载线程安全的统计对象，新增 `internal/rules/traffic.go` 协调采样、落盘和重置，避免把统计写入生命周期预算对象。

## 接口契约

- `Rule` 和 `Input` 增加 `traffic_enabled`；输入使用可选布尔值。新增省略为 false，修改省略保留旧值，显式 null 按省略处理；其他类型拒绝。
- Rule 输出增加 `traffic` 对象，包含 `upload_bytes`、`download_bytes`、`upload_bytes_per_second`、`download_bytes_per_second`。
- 累计字节在数据库中使用非负 64 位整数，JSON 使用十进制字符串，前端边界校验后以 BigInt 格式化，避免长期累计超出 JavaScript 安全整数范围。速度使用有限非负数值，单位 B/s。
- 不接受客户端提交累计值或速度，保持输入与输出契约隔离。
- `POST /api/rules/{id}/traffic/reset` 使用现有登录、Origin、CSRF 和 `If-Match` 校验；成功返回 200、最新 Rule 和 ETag。重置成功增加 revision 并更新 updated_at；周期采样和落盘不增加 revision。
- 不存在返回 404、版本过期返回 412、存储失败返回 500，沿用统一错误结构。
- 新增、修改、启停与重试响应均包含相同统计契约；恢复、重试和前端 `ruleInput` 构造都需保留统计开关。

## 存储与迁移

- 增加版本 3 迁移：rules 新增 `traffic_enabled INTEGER NOT NULL DEFAULT 0` 与布尔 CHECK；新增按 rule_id 主键关联的累计统计表，保存上下行字节数，删除规则时事务性删除或级联删除。
- 使用增量 ALTER，不重建 v2 rules 表；保留原有字段、规则 ID、revision、时间文本、索引和触发器。
- 支持空库、v1 经 v2 到 v3、现有 v2 到 v3；迁移失败回滚，未来版本拒绝启动。
- 配置保存和统计写入分离，避免编辑名称时使用过期快照覆盖累计值。
- 批量落盘、重置和删除由服务串行协调；重置事务同时写入清零统计和新 revision。异步快照不得在重置或删除后回写旧值或复活已删除记录。
- 定时写入失败保留脏标记和累计值并报告错误，下一周期重试，禁止预先标记成功。

## 生命周期与并发

- 数据路径不得持有服务锁，也不得调用数据库。锁顺序由服务协调锁到统计对象锁，转发路径只访问统计对象，防止 Stop 等待会话时死锁。
- 开关在配置持久化成功后生效，共享统计对象使已有 TCP 长连接与 UDP 会话也能切换计数；不通过 Runtime.Update 切换统计，避免取消 generation 和断开会话。
- 默认关闭不累计字节、不为该规则产生无意义的持久化写入；计数路径保持固定内存使用，验证额外开销。
- 重置以数据库事务成功为最终确认：短暂锁定统计对象并划分新旧统计代，解锁后执行清零事务，期间新流量进入临时新代。成功则保留新代并丢弃旧代；失败则合并旧累计与期间增量并恢复原有采样语义。数据库 I/O 不持有统计对象锁，查询与管理写入由服务锁等待重置完成；重置之前的数据不能稍后重新加入。失败不丢累计值，不改变开关、revision 或连接。
- 重置时同时重建速度基线；采样结果不得出现负数、NaN 或跨重置尖峰。重置后的新流量可以立即累计。
- 统计关闭、规则停用或故障停止时速度归零，保留累计值；改名、修改目标/监听/协议沿用规则 ID 的累计值。
- 关闭服务时先禁止新管理写入、停止采样循环并等待退出，再停止运行组并等待所有会话结束，最后刷新完整累计量；数据库在服务之后关闭。Close 必须幂等；main 通过统一 defer 关闭服务并合并最终保存错误，避免重复调用路径。
- 最终落盘失败须明确报告，不能将未成功持久化描述为已保存。

## 前端交互

- 规则编辑器增加“流量统计”开关，独立于“启用规则”，新增默认关闭。
- 桌面表格与窄屏卡片共用统计展示逻辑：上下行累计量及 B/s 自适应单位；关闭时仍显示累计值和“统计已关闭”。
- 统计区提供“重置流量”按钮，无论统计开关或规则启停状态均可操作；复用 Modal，确认文案说明清空累计量且不影响转发。按钮保留可访问名称和忙碌禁用。
- 成功使用后端响应更新规则及 revision；失败保留旧数据，412 引导刷新，不静默覆盖。避免提交前启动的旧轮询结果覆盖重置后的快照。
- 页面只呈现功能文案，不展示需求说明或实现细节。

## 取舍、上线与回滚

- 载荷字节统计可以由应用准确观测，不等同于网卡层总流量，不引入抓包、宿主机权限或防火墙依赖。
- 每秒采样、每 5 秒落盘可降低 SQLite 写入量；磁盘正常且刷新成功时强制退出可能丢失最近一个周期附近的增量。持续存储失败将扩大未落盘窗口，日志必须可见。
- 启用计数会增加数据路径工作量；实现应避免按字节分配或每条规则独立采样协程。
- 发布前备份完整数据；v3 库不能交给旧程序直接打开，回滚同时恢复旧程序与升级前数据备份。
