# 顶部导航与 README 文案优化

## 目标

将后台页面导航整合到页头，减少内容区域上方独立按钮栏的占用；让 README 首段聚焦端口转发、持久化和部署能力，弱化语言支持描述。

## 用户原始需求

1. 后台的菜单可以放到顶部，而不是单独一排按钮。
2. README 里不要写什么中文/英文界面，语言支持不是项目特点，可以弱化这方面描述。

## 已确认的现状

- `web/src/App.vue:489` 起的登录后页头包含品牌、静态栏目标题和账户操作；页面切换导航目前位于主内容区内。
- `web/src/App.vue:36` 定义管理员套餐、用户及系统配置入口；管理员和用户后台共享导航结构，入口和接口仍各自独立。
- `web/src/style.css:510` 起定义页头布局，已有窄屏适配；导航调整需要兼顾菜单和账户控件的可用空间。
- `README.md:5` 和 `README.zh-CN.md:5` 在首段宣传界面语言；两份文档第 3 行为文档切换入口，末尾开发发布说明还包含工作流语言约定。

## 已确认的方案与要求

- R1：管理员和用户后台均将页面菜单放入顶部页头，移除主内容区原有的独立导航按钮栏。桌面采用文字导航和明确的当前选中态，利用品牌右侧原静态栏目标题的位置。
- R2：窄屏通过页头菜单按钮展开导航；选择页面后收起。保留语言切换、账户和退出操作，菜单具备可访问名称、展开状态和键盘操作能力。
- R3：保留现有页面集合、切换行为、请求进行中的操作保护，以及两个后台的身份与接口隔离。
- R4：同步修改两份 README，删除首段中关于中文/英文界面的宣传，删除与使用者无关的工作流语言约定；保留双语文档链接及产品语言切换能力。

## 验收标准

- AC1（R1）：管理员可以通过页头访问转发规则、套餐管理、用户管理和系统配置；用户可以通过页头访问转发规则和账户概览。正文顶部不再出现原菜单按钮栏，当前页面可识别。
- AC2（R2）：桌面及 390px 窄屏下，现有两种界面语言均无导航或账户控件重叠、截断导致的不可操作；窄屏菜单可以打开、切页和关闭，并支持键盘。
- AC3（R3）：验证切页、退出及现有忙碌状态保护；前端现有测试、静态检查和构建通过。
- AC4（R4）：两份 README 不再将界面语言作为项目卖点，文档切换链接仍有效，其余使用与部署说明保持准确。

## 范围外

不调整业务功能、套餐和配额规则、数据库、鉴权及 API；不引入路由框架，不重新设计规则表格，不移除翻译或语言切换功能。实现验收后，用户已明确授权提交、合并主分支、删除开发分支并推送。

## 验证与风险

主要风险是窄屏及英文菜单占用页头空间。实现后检查桌面和窄屏实际页面，并执行前端 lint、类型检查、现有测试和构建。该任务无需数据迁移；无需要延期的技术问题。

轻量任务，使用本 PRD 作为需求与执行依据，已完成仓库调研和需求归并。用户已在最终方案后回复“是”，明确批准本版方案进入实现。
