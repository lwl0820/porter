基线：main `823360c9f8727d98146cd11656b1d7f54d47a96f`（v0.4.1）。

- `internal/localapi/server_linux.go:39`：Start 仅原生环境可用，校验固定管理员并提供独立Unix控制服务；真实UID0校验继续生效。`internal/controlapi/protocol.go:21` 已有 /v1/rules 只读查询，可评估作为CLI就绪检查复用点。
- `scripts/install.sh:206`：read_environment 目前固定要求四个配置键和非空凭据。`env-write/env-read` 约509行，collect_input约704行，三类输入无条件收集。
- `scripts/install.sh:440`：升级依赖health参数，约480行使用curl /healthz；首次安装约1227行也仅支持HTTP就绪。两条路径及失败回滚均需按模式处理，不得只改首次输入。
- 服务unit、schema2 split安装、schema1升级迁移、托管PATH、语言偏好、purge边界及锁/恢复合同见 backend/native-install-contracts.md；产品交互改变须同步双语安装器文案与两份README。

## 需要重点设计的边界

1. Web未开启时没有HTTP监听但后台转发和SO_PEERCRED本机控制仍正常。
2. 不再要求凭据不意味着去掉管理员身份或降低本机授权。
3. 既有安装无新模式字段的兼容、升级后的模式保持、健康检查与回退都要一起设计。
4. 不机械增加另一套发行包；本任务的用户价值是不用开启Web服务。

## 新增三模式选择的影响

- 用户确认 Web 与 CLI 可分别选择、至少一项、默认两者均启用，首次安装不再只有“关Web”一个开关。
- `scripts/install.sh:263` validate_state只接受schema1/2，schema2要求split，并默认双程序；后续`state-write/state-read`、完整性校验、卸载与升级复制/备份程序列表均依赖此布局。仅Web不能只跳过复制客户端而保留原双程序完整性校验，需记录所选功能并贯穿生命周期。
- schema2旧版记录对应双入口，schema1旧版记录对应Web单入口；升级兼容需要区分旧布局和用户新选择，不能把缺失布尔值一律当关掉或一律新增CLI。
- `internal/native/native.go` 当前按平台与容器判断本机控制可用，没有安装功能选择。新的CLI关闭需在服务启动时不调用控制服务，保持原native/dockertag边界。
- 初始化安装目前会无条件调用check_command及校验已有porter路径。仅Web新装不应因为未知同名系统命令而拒绝无关Web部署；也不能接管、删除其他来源的porter命令。

本功能的服务配置、安装状态、运行时与健康检查互相依赖，作为一个任务统一验收，不拆成无法单独使用的功能子任务。

## 最终方案收敛

用户选择支持重跑安装器切换组合、保留规则及数据。已在PRD R3/AC5—AC6和design事务章节记录。

补充代码证据：
- `internal/store/migrations/004_accounts.sql:25` 固定管理员在迁移时已经创建，初始用户名为空；仅CLI可直接GetUser(AdminID)，无需强造用户名或密码。
- `internal/rules/service.go:73` 无条件SplitHostPort且约490行保留管理端口；传空地址表示无Web需要调整构造校验与相关测试，不能只跳过HTTPserver。
- Docker/非Linuxstub实际位于 `internal/localapi/server_other.go`，按构建标签禁用；native检查仍须生效。
- 新安装脚本可能被用于尚未支持模式的旧发行包，预检必须识别能力。设计新增无副作用的porterd --check-config，对候选配置进行预检并拒绝旧程序不支持情形；历史原版本恢复路径保留兼容。

规划已收敛为单一可验收功能，不另建子任务；服务入口、安装记录和切换事务共同满足用户目标，独立交付任一层都不足以提供功能。当前只写任务文档，产品代码与Git分支未改变。
