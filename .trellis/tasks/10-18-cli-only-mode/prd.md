# 支持按需安装 Web 与命令行

## 目标

原生 Linux 用户通过交互式安装选择 Web 与命令行管理入口，默认两者均安装、至少启用一种。仅命令行模式无需配置 Web 凭据或监听地址；安装后可重跑脚本切换组合并保留规则与业务数据。

## 背景与现状证据

基线 main `823360c9f8727d98146cd11656b1d7f54d47a96f`（v0.4.1）。

- `internal/config/config.go:26` 无条件要求管理员凭据并校验 HTTP 地址；`cmd/porterd/main.go:65` 无条件初始化 Web 监听和认证。
- `internal/rules/service.go:73` 要求管理监听地址，约490行按其保留管理端口；Web 关闭时需要准确表达不存在该监听。
- `scripts/install.sh:206` 解析配置时强制四个字段；约704行无条件收集用户名、密码和监听地址；约480及1227行的升级/安装就绪检查都依赖 HTTP `/healthz`。
- `scripts/install.sh:263` 的 schema1/2及split布局不能表达“仅Web不安装客户端”；程序完整性、入口、升级和卸载都依赖该假设。
- `internal/store/accounts.go:62` 的 EnsureAdmin 会改名固定管理员且拒绝空用户名；`internal/store/migrations/004_accounts.sql:25` 已创建固定管理员身份。纯CLI不得因缺Web用户名意外改名、创建替代账号或改变规则归属。
- 客户端通过原生 Unix socket 管理规则，后台转发服务仍须运行；平台与容器授权边界、PATH和语言偏好契约见现有后端规范。

完整影响说明见 `research/现状与影响范围.md`。

## 已确认需求

### R1 安装选择

- 交互式安装分别询问是否启用 Web 和 CLI，每项默认启用；有效组合为两者、仅Web、仅CLI。
- 两者都关闭时提示并重新选择，不停止服务或写入安装/业务配置。
- 所有选项、校验、确认和结果沿用安装器中英文，语言仍先于业务输入。

### R2 按选择提供管理入口

- 后台 `porterd` 始终承载转发及选中的管理入口。
- 仅CLI：不启动任何 Web TCP 监听、Web 页面、登录/API及HTTP健康入口；安装不询问或要求Web用户名、密码、地址，默认HTTP端口被占用也不影响启动。
- 仅Web：不部署 `porter` 客户端、不创建其托管PATH入口或本机控制socket；Web管理和转发正常。
- 双入口：保持现有功能，操作同一数据库和规则服务。
- CLI保留root/sudo管理员权限、交互/参数规则CRUD、双语和语言保存；不存在离线写库或另启服务行为。

### R3 安装后切换

- 用户确认采用建议：通过重跑安装脚本切换三个有效组合，保留规则、统计、用户、套餐和数据目录。
- 已安装实例以当前组合为选择默认值，未选择更改时保持现状；显式升级也保留组合，不把新装默认套用到旧实例。
- 切换展示当前与目标组合、配置变化及服务重启影响，确认后执行。取消/EOF/中断输入不提交改变。
- 首次开启Web且无可复用合法配置时收集用户名、隐藏密码与确认、监听地址；已有合法Web配置复用，关闭Web不删除原Web配置。
- 关闭CLI仅移除确认归属的客户端与PATH入口；CLI语言偏好保留，再开启时复用。
- 切换失败恢复原组合、程序、入口、配置和服务状态；强制中断后重跑能恢复，不能留下两种入口均不可用却报成功的状态。

### R4 生命周期与兼容

- 安装状态明确记录组件组合，贯穿完整性检查、重跑、升级、卸载、恢复和purge。
- schema2旧双程序安装解释为双入口；schema1旧单程序普通重跑/恢复继续原版本及布局，启用新组件选择前必须显式升级到支持该功能的版本。迁移维持原有可用入口，之后允许用户显式切换。
- 不支持新功能的目标程序须在切换前识别并拒绝，不能让旧版本忽略新配置后继续开启Web而宣称已关闭。
- 就绪检查匹配选中的管理入口；双入口需两种都正常，只有进程活着不等于管理可用。
- 普通卸载保留正式配置、偏好和业务数据；purge仍精确删除正式服务/CLI配置及数据，历史备份保留规则不变。
- Docker默认仍为Web服务、无CLI或本机控制，不能通过配置绕过容器禁用边界。

## 不包含

- 新增用户管理、套餐管理或离线数据库CLI。
- 单独发行一套移除Web资源的程序包；未开启Web指运行时不提供Web服务。
- Docker命令行管理、无任何管理入口的运行模式。
- 切换时保持已有转发连接不断开；本次采用服务重启。

## 风险与边界

切换需要短暂停服，既有连接可能断开。复用已有备份与回退保护，保持锁、归属和文件类型校验。备份可能含旧Web凭据，沿用root受限权限及历史备份清理策略。运行模式不改变业务数据库schema；验证须区分命令替身、命名空间内真实程序与真实systemd宿主。
