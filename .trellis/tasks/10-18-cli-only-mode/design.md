# Web 与命令行可选安装设计

## 1. 架构与数据流

交互安装/重配置 → 受限服务配置与组件安装记录 → systemd启动 `porterd` → 同一规则服务与数据库 → 按需启动Web或Unix本机管理。发行包继续同时包含porter/porterd；本机只部署所选客户端及始终需要的服务端。

服务与安装器共同接受三种组合，双关为配置错误。客户端继续只通过控制协议调用服务，不读数据库。Docker与非原生平台的本机管理固定不可用，不能将CLI启用开关视为解除native限制。

## 2. 配置与启动合同

- 新增 `PORTER_WEB_ENABLED`、`PORTER_CLI_ENABLED` 布尔环境配置，原生缺省均为true，保持直接运行旧配置的兼容。非法布尔或显式双false拒绝。Docker实际CLI仍不可用；Web关闭且无原生控制能力时明确拒绝无管理入口运行。
- Web启用才读取/要求管理员凭据、校验HTTP地址与Web专用cookie设置、绑定TCP、构建认证/页面handler；关闭时不以无效或缺失Web配置阻止CLI启动。共享数据库/转发限制仍无条件校验。
- CLI启用且native可用才创建本机socket；CLI关闭不创建控制节点，现有退出inode归属清理规则不变。
- Web启用沿用EnsureAdmin配置管理员名；Web关闭则读取迁移已创建的model.AdminID固定记录，不改名、不造Web密码。固定ID/管理员角色校验仍在本机管理入口执行。
- `rules.New(..., adminAddr, ...)` 允许空adminAddr明确表示没有管理TCP监听，禁止用虚构地址/端口替代；仅真实管理监听参与端口冲突校验。启用Web传实际已绑定地址。
- 抽离共享启动与停止路径，按需创建listener/server。无HTTP服务时仍监听进程退出信号，关闭本机请求后等待规则服务保存，最后关库；部分启动失败应关闭已取得资源并报错。

### 启动预检能力

新增 `porterd --check-config`：只加载并校验配置及当前环境可用管理方式，不打开数据库、不监听、不写语言设置；成功0，错误非零，错误不包含凭据。安装器把受限解析后的候选配置传入子进程环境，不以命令行参数或日志携带密码。该能力同时识别旧程序不支持组件配置，避免旧程序静默忽略开关。版本查询和参数拒绝语义继续测试。

新功能的新装/切换及升级候选执行预检；旧schema1/2原版本原样重试、卸载/恢复沿用旧路径，不要求历史程序支持新命令。显式指定不支持此功能的候选版本不得部署并宣称支持组件选择，须在停服前提示升级版本限制。

## 3. 安装记录与文件归属

采用schema3扩展既有安装记录，固定layout=split，增加严格对象 `features:{web:bool,cli:bool}`，必须至少一项true；保留directory/arch/version/status及受限command_link。不得依赖“找不到porter文件”猜测功能关闭。

- 服务端porterd始终是托管必需文件；客户端porter只在features.cli=true时是必需文件。command_link只可在CLI启用、确实管理/usr/bin/porter时存在，安装目录直接为/usr/bin时不自链接。
- Web-only不检查或管理无关系统PATH上的同名porter，启用CLI时再作既有归属和冲突预检。关闭CLI只删除状态与文件校验能证明归属的本体/链接。
- 原配置文件名、unit服务名、数据库及数据路径不变；/etc/porter/porter.env保存明确组件开关。新CLI-only不写Web凭据/地址键；Web曾启用时关闭后保留合法旧字段供以后复用，运行时忽略。
- /etc/porter/cli.json不随关闭CLI删除；CLI共享主机偏好不由安装器选语言预填，普通卸载保留，purge仍精确清理。
- schema2解释为split双入口；schema1解释为legacy Web入口。旧程序不支持组件变更时先要求显式升级，不能以新客户端覆盖旧服务。迁移至新支持版本保留实际原入口组合；旧split继续双入口，旧legacy继续Web，再可重跑启用CLI。
- schema3的env与state组件选择必须一致；不一致、未来schema或未知字段不静默归零，按可信恢复记录处理或明确拒绝。完整性检查按托管组件执行，不能取消缺库保护。

## 4. 交互与操作边界

### 新装

语言选择后分别询问Web/CLI是否启用，默认均是；双否重新选择。先完成组合及所需Web配置收集，再提交安装。仅CLI无Web三项输入；提示服务、配置与CLI位置，不能展示不存在的Web入口。仅Web不展示可用CLI命令。

### 已安装实例

普通重跑展示当前组合，提供是否修改组件的选择（默认不修改）；选择修改后以当前组合为逐项默认值。无变更保持幂等，不下载最新版、不重启。支持六方向变更。首次开启Web缺合法配置才收集三项配置；已有合法配置复用，不能回显密码。

补装CLI时仅下载/校验当前记录的同版本发行包，验证程序版本、预检能力和所需文件；不把组件变更变为隐式版本升级。关闭CLI不需要下载。普通卸载后重装按原组件/版本恢复，完成后可用重跑修改，避免把恢复与版本变更混在一起。

显式--upgrade保持当前组合，备份/程序清单和就绪均按组件处理。--uninstall/--purge不询问启用选项，所有确认仍先于状态变更。

### 确认

切换前显示原/目标组合、必要文件变化、备份位置和重启影响，显式确认后持双锁重校原状态、env、程序/入口归属和unit快照。EOF、INT、TERM或取消不提交。重启前检查候选配置、所需包和资源冲突。

## 5. 切换事务与恢复

复用当前显式升级的持久事务和备份/回滚代码，增加operation区分upgrade与reconfigure，避免再写一套不一致的恢复逻辑。持久状态仍使用受限upgrade_id和upgrading，transaction记录操作种类、原/目标features与严格受限阶段；路径仅由可信安装目录及ID推导，不信任任意JSON路径。CLI偏好在不稳定状态/全局锁期间沿用现有拒绝写入策略。

顺序：预检与确认 → 双锁重校 → 写可恢复prepared → 停服确认 → 完整备份 → backup_complete → 切换env/所选程序/托管入口 → 候选启动与按模式就绪 → 恢复原active/enabled意图 → 原子提交complete。

- 原install.json精确字节、程序、unit、服务配置、CLI偏好及完整数据目录含owner/mode备份；不能复制运行中的单DB文件冒充备份。DATA本体挂载根的限制沿用现有升级保护，在停服前拒绝。
- 操作失败或信号按持久阶段恢复，先停止候选进程，禁止合并新旧数据；恢复程序/配置/数据/托管链接及原active/enabled意图。原本停止的实例只临时启动验收，再停止。
- 备份完成前不得将半备份用于回退；恢复过程本身可重入。强制中断后下一次安装/升级/卸载先完成恢复再处理新请求。保留唯一备份与明确双语指引，沿用原残锁处理，不递归删除未知锁。
- 历史备份与失败新数据目录的保留、权限和purge说明沿用现有合同。组件禁用不删除业务规则/用户/统计，仅后台重启可能断开当前连接。

### 重开Web的规则端口保护

HTTP先绑定再恢复规则时，冲突的规则可能只标listen_failed，健康检查仍成功，因此重开Web须在停服前检查现有启用TCP/组合规则与目标监听是否重叠。活跃CLI实例优先root Unix只读查询；原已停止实例允许安装器对固定可信DB作SQLite mode=ro/query_only固定SELECT（当前DELETE journal），读失败拒绝，不开Store、不迁移/恢复热日志、不改业务字节或owner/mode。不使用immutable跳过恢复。确认前与锁内均重校，原有规则不能被新Web挤占。

## 6. 就绪检查

| 组合 | 必须验证 |
| --- | --- |
| Web+CLI | HTTP /healthz精确成功、Unix控制只读查询成功、对应本体/PATH与unit状态正常 |
| 仅Web | HTTP /healthz成功、无托管CLI与本机socket |
| 仅CLI | root通过Unix socket执行现有GET /v1/rules返回正确JSON、无WebTCP监听；无需WebURL |

控制检查从受信任root安装进程使用已有Unix HTTP协议，响应结构及错误码须校验；不借助增加未授权HTTP端点、不要求CLI首次选语言、不写语言偏好，不靠socket文件存在即报可用。服务active检查在探测前后执行，首次安装还确认enabled。卸载与显式恢复仍按原服务意图处理。

## 7. 兼容、风险和不做

已有发行包继续双程序，不为模式增加新构建矩阵；Docker继续只编译服务和本机stub。业务数据库schema不改变，管理员固定ID保持。运行时无Web不代表二进制移除嵌入的Web资源。

切换要重启服务，会断开现有连接；不承诺热切换。Web重新启用可能与现有规则端口冲突，候选启动及就绪失败须回退。隐藏密码和旧凭据备份按0600/0700保管，文档明确正式purge与历史备份边界。
