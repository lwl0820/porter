# 前端交互与接口契约

## 1. 范围与触发条件

适用于 `web/` 中 Vue 3、TypeScript、Vite 的管理界面、请求封装和前端嵌入。产品界面支持中文和 English，不展示开发需求、验收清单或任务过程文字。

## 2. 签名与模块职责

- `src/api.ts`：唯一 fetch 与运行时响应校验边界，导出 `api`、`ApiError`、`setSession`。
- `src/types.ts`：Rule、RuleInput、Session、FieldErrors 契约；规则输入包括独立的 traffic_enabled 开关，Rule 另含只读 traffic；`protocols`、`protocolDetails`、`isProtocol`、`matchesProtocol` 集中维护协议选项、展示与筛选。
- `src/App.vue`：登录、列表、搜索筛选、轮询与写操作协调。
- `src/components/RuleEditor.vue`：规则表单、字段校验、转发变更提示。
- `src/components/Modal.vue`：原生 dialog、初始焦点与关闭后焦点恢复。
- `web/embed.go`：`Handler() http.Handler`，内嵌 `dist` 并提供静态文件服务。

## 3. 请求与状态契约

所有请求同源，Cookie 不进入 localStorage；登录或会话恢复后保存内存 CSRF token，修改请求通过 `X-CSRF-Token` 发送。PUT、DELETE、重试使用带引号的 `If-Match`。GET 列表解析 `{rules: Rule[]}`，新增和修改解析单条 Rule。

新增和修改只序列化 RuleInput，不能展开完整 Rule 回传元数据。所有 unknown 响应在 api.ts 中校验，组件不重复类型断言。412 提示关闭编辑器并刷新，不静默重试覆盖。

`Protocol = "tcp" | "udp" | "tcp+udp"`，新增与编辑提供三项单选，组合值直接通过一次请求保存同一条规则，不在前端拆成两次请求。列表展示 TCP+UDP、一行、计数一条，编辑回显组合选项，整体启停/删除/重试。TCP 筛选包含 TCP 和组合，UDP 筛选包含 UDP 和组合，TCP+UDP 筛选仅组合。显示名称、图标和 CSS 类由集中元数据取得，组合 CSS 类为 `both`，不能将 `tcp+udp` 直接拼成选择器。

列表每 5 秒同步，隐藏页面暂停；刷新失败保留上次数据并提示。提交期间禁止重复写操作，保存成功关闭编辑器后仍需复位全局 busy，不能依赖子组件卸载后的事件。没有全局状态框架，简单状态放组件内。

## 4. 校验与错误矩阵

| 情形 | 界面行为 |
| --- | --- |
| 401 | 退出当前管理态并显示登录。 |
| 字段错误 | 显示在字段旁，取消禁用后聚焦第一个错误。 |
| 409 监听冲突 | 保留表单，显示服务端原因。 |
| 412 版本过期 | 不覆盖最新规则，要求刷新。 |
| 请求失败 | 保留已有列表，允许重试。 |
| 空列表、筛选无结果 | 分别提供新增入口或清除筛选。 |
| 修改转发参数、停用或删除 | 明确说明会断开该规则现有会话。 |

## 5. 正常、基础与异常案例

- 正常：桌面表格与窄屏卡片可完成相同操作；TCP、UDP 与 TCP+UDP 标签清晰。桌面协议单选三列，窄屏 TCP/UDP 同行、TCP+UDP 独占下一行。
- 基础：名称、协议、监听 IP 与端口、目标主机与端口、启用状态组成完整输入。
- 异常：网络断开后仍可看到之前规则；会话过期不会一直留在不可操作页面。
- 无障碍：状态包含文字，按钮和表单有可访问名称，原生 dialog 管理焦点，删除默认焦点落在保留操作。

## 6. 必需验证

执行 `npm --prefix web run lint`、`type-check`、`test`、`build`；Vite build 不代替 TypeScript 检查。交互测试位于 `src/App.test.ts`，应以用户行为验证登录、CRUD、提交防重、字段错误、revision、CSRF、隐藏暂停轮询与过期退出。

组合交互测试断言单次新增请求携带 `tcp+udp`、一行一条计数、三种筛选包含关系、编辑回显与协议切换，以及整体启停删除。不因增加协议删除原有 TCP/UDP 用例。

必须实际浏览器检查窄屏。CSS 隐藏文字时，退出和刷新图标按钮必须保留显式 aria-label，不能只靠 SVG 或 title。对最终构建产物再执行 Go 构建，避免并发 npm build 清空 dist 导致 embed 失败。

## 7. 错误与正确写法

错误：`JSON.stringify({...rule, ...form})`，会把 id、status、revision 发给严格后端。

正确：只构造 RuleInput；revision 在 If-Match 头传递，运行态由后端返回。

错误：窄屏用 `display:none` 隐藏按钮中的 span，却没有 aria-label，导致按钮在辅助功能树中没有名称。

正确：退出按钮使用 `aria-label="退出登录"`，刷新使用 `aria-label="刷新规则"`，并保留相应回归断言。

错误：协议筛选直接使用 `rule.protocol === selectedProtocol`，导致组合规则在 TCP/UDP 下消失。

正确：使用 `matchesProtocol(rule.protocol, selectedProtocol)`，空值包含全部、组合筛选只含组合，单协议筛选同时包含相应单协议和组合。

源码依赖与锁文件同时更新；临时文件、npm 缓存、构建测试输出使用仓库 `.tmp/` 或被忽略的项目子目录，不访问系统临时目录。

## 8. 场景：流量展示与重置

### 8.1 范围与触发条件

修改规则统计开关、载荷字节展示、速度、重置或列表异步协调时适用。桌面与窄屏共享统计展示与格式化行为。

### 8.2 签名与边界

- RuleInput 增加 `traffic_enabled: boolean`，新增默认 false；Rule 包含只读 traffic 对象。
- `api.ts` 是统计响应校验的唯一边界；组件只能读取校验后的类型。
- 重置调用 `POST /api/rules/{id}/traffic/reset`，沿用内存 CSRF 与 If-Match，返回最新 Rule 后更新 revision。

### 8.3 数据与交互契约

累计字节 `upload_bytes/download_bytes` 是非负十进制字符串，格式化先用 BigInt，禁止先转为 Number 丢失精度。速度是有限非负数值，按 B/s 及二进制单位展示。上行指客户端到目标，下行反向，组合规则使用后端汇总，不另行相加。

编辑器的“流量统计”独立于“启用规则”；ruleInput、启停与编辑提交均保留此字段，不能回传 traffic。统计关闭显示关闭状态及保留的累计量，速度为零。

统计区提供重置按钮，关闭统计或停用规则时也能使用；弹窗确认会清零累计量但不影响连接，取消不请求。提交期间阻止重复，成功使用返回规则更新；操作前发起的旧轮询结果不得覆盖重置/保存后的快照。保持每 5 秒刷新与隐藏暂停行为。

### 8.4 校验与错误矩阵

| 条件 | 行为 |
| --- | --- |
| 缺失/非法统计字段、负值、NaN 或无限速度 | 解码拒绝，提示响应无效，保留已有列表。 |
| 重置失败 | 保留统计及弹窗可重试状态，不伪造清零成功。 |
| 过期版本 | 412 引导刷新，不自动重试覆盖。 |
| 会话过期 | 返回登录态。 |

### 8.5 正常、基础与异常案例

- 正常：真实持续转发时数值刷新，重置后重新累计，组合规则仅显示一套汇总。
- 基础：新增统计关闭、编辑回显、保留旧累计；重置按钮及弹窗在窄屏可用且有可访问名称。
- 异常：旧 GET 响应迟到不会恢复重置前数值；重置网络失败保留已有累计。

### 8.6 必需测试

行为测试覆盖默认值、开关序列化、编辑与启停保留开关、上下行与超安全整数格式、重置取消/成功/失败/412、防重复和旧轮询竞争。实际浏览器检查桌面与窄屏的统计区、重置确认、焦点和布局。

### 8.7 错误与正确写法

错误：`Number(rule.traffic.upload_bytes)` 后再格式化；只在已开启统计时允许重置；重置返回后让旧列表请求覆盖最新值。

正确：累计字节用 BigInt 格式化，统一组件同时用于表格与卡片；重置不依赖开关，使用请求序号或取消旧读取阻止迟到响应覆盖。

## 9. 场景：中英文界面与提示

### 9.1 范围与入口

新增或修改产品可见文案时适用，包括启动/登录、管理页、表单、确认弹窗、错误、通知、占位符、title 和 aria-label。内部会话、文档及注释保持中文。

登录表单保留 required 属性并使用 novalidate，由页面显示所选语言的缺失提示、聚焦相应输入并阻止请求；不能依赖浏览器原生校验气泡，其文案由浏览器 UI 语言决定。

### 9.2 签名与职责

- `src/i18n.ts`：`Language = "zh-CN" | "en"`，共享只读 `language`，提供 `initializeLanguage()`、`setLanguage(value)`、`t(key, params?)` 和 `knownMessage(message)`。
- `MessageKey` 从集中英文词典键推导，中文原文即词条键；插值参数通过 `t("共 {total} 条规则", { total })` 传递，不能按中文语序拼接英文。
- `src/components/LanguageSwitcher.vue`：统一切换入口，选项固定为“中文”和“English”，可访问名称随当前语言变化。
- `api.ts` 的 `errorMessage(error)`、`fieldErrorMessage(field, message)`、`ruleErrorMessage(rule)` 在展示时翻译；继续作为已校验错误与 UI 之间的边界。

### 9.3 语言与数据契约

偏好键为 `porter.language`。首次默认中文，合法持久值优先；读取异常或值无效时回到中文，写入异常不阻止当前页切换。初始化及切换同步 `html.lang`、文档标题和 description。语言变更不刷新页面、不发业务写请求，不清除输入、筛选或错误。

组件渲染或 computed 中调用翻译函数，使文案响应语言变化。持续显示的错误保留原始 ApiError 或原文键，成功通知保留词条键；不能在请求失败时缓存已经翻译的字符串。协议描述和状态标签同样在展示时翻译。

规则名、账号、地址、协议标识、字节单位及其他用户数据保持原值。语言偏好不存储 Cookie/CSRF，也不改变接口载荷、revision、轮询或流量精度。

### 9.4 错误矩阵

| 条件 | 行为 |
| --- | --- |
| 已知 API code | 映射当前语言提示；412 仍要求关闭表单并刷新。 |
| 字段原因 | 先识别已知原因，保留目标单播、IP、端口等不同约束。 |
| 监听失败 | 翻译后端有限模板，保留 TCP/UDP 诊断及停用后修改重叠地址的建议。 |
| 未知错误 | 显示当前语言的通用错误，不让原始未知中文泄漏到英文界面。 |
| 已显示错误时切换 | 原提示与对应字段立即更新，表单输入及焦点流程保留。 |
| localStorage 不可用 | 界面可用且可切换，本页语言仍生效。 |

### 9.5 场景与验证

默认中文；切换 English 后登录、列表及弹窗使用英文；刷新/退出登录仍保留语言。规则中文名称在英文页面仍为原名。桌面和窄屏中语言入口可达，长英文不遮挡操作。

新用例覆盖语言偏好、非法值和存储异常、英文客户端与服务端错误、已显示错误/通知切换、输入保留及元信息。共享语言状态与 localStorage 在每例前复位，避免污染原有中文业务用例。执行本规范第 6 节质量门禁，实际检查两种语言和窄屏。

### 9.6 错误与正确写法

错误：`error.value = t("操作失败，请稍后重试。")`，再直接渲染字符串，切换后仍显示旧语言。

正确：保留错误对象或词条键，在模板中调用 `errorMessage(error)` 或 `t(key)`；动态名称和计数使用词条参数，Vue 负责文本转义。
