# 前端交互与接口契约

## 1. 范围与触发条件

适用于 `web/` 中 Vue 3、TypeScript、Vite 的管理界面、请求封装和前端嵌入。产品界面支持中文和 English，不展示开发需求、验收清单或任务过程文字。

## 2. 签名与模块职责

- `src/api.ts`：唯一 fetch 与运行时响应校验边界，`createClient(role)` 创建独立客户端，导出 `adminApi`、`userApi` 和 `ApiError`；setSession/onUnauthorized 属于各自客户端，不使用共享全局 CSRF。
- `src/types.ts`：Rule、RuleInput、Session、FieldErrors 契约；规则输入包括独立的 traffic_enabled 开关，Rule 另含只读 traffic；`protocols`、`protocolDetails`、`isProtocol`、`matchesProtocol` 集中维护协议选项、展示与筛选。
- `src/admin.ts`、`src/AdminApp.vue` 和 `src/user.ts`、`src/UserApp.vue`：独立页面入口与根组件；`src/App.vue` 复用登录/规则布局，但角色由入口固定，不能从会话切换成另一端。
- `src/components/RuleEditor.vue`：规则表单、字段校验、转发变更提示。
- `src/components/Modal.vue`：原生 dialog、初始焦点与关闭后焦点恢复。
- `web/embed.go`：`Handler() http.Handler`，内嵌 `dist` 并提供静态文件服务。

## 3. 请求与状态契约

所有请求同源，Cookie 不进入 localStorage；登录或会话恢复后保存内存 CSRF token，修改请求通过 `X-CSRF-Token` 发送。PUT、DELETE、重试使用带引号的 `If-Match`。规则路径分别在 `/api/admin` 和 `/api/user` 下，GET 列表解析 `{rules: Rule[]}`，新增和修改解析单条 Rule；管理端规则还须校验 owner 与 owner_id 一致。

新增和修改只序列化 RuleInput，不能展开完整 Rule 回传元数据。所有 unknown 响应在 api.ts 中校验，组件不重复类型断言。412 提示关闭编辑器并刷新，不静默重试覆盖。

`Protocol = "tcp" | "udp" | "tcp+udp"`，新增与编辑提供三项单选，组合值直接通过一次请求保存同一条规则，不在前端拆成两次请求。列表展示 TCP+UDP、一行、计数一条，编辑回显组合选项，整体启停/删除/重试。TCP 筛选包含 TCP 和组合，UDP 筛选包含 UDP 和组合，TCP+UDP 筛选仅组合。显示名称、图标和 CSS 类由集中元数据取得，组合 CSS 类为 `both`，不能将 `tcp+udp` 直接拼成选择器。

列表每 5 秒同步，隐藏页面暂停；刷新失败保留上次数据并提示。提交期间禁止重复写操作，保存成功关闭编辑器后仍需复位全局 busy，不能依赖子组件卸载后的事件。没有全局状态框架，简单状态放组件内。

## 4. 校验与错误矩阵

| 情形 | 界面行为 |
| --- | --- |
| 401 | 退出当前管理态并显示登录。 |
| 字段错误 | 显示在字段旁，取消禁用后聚焦第一个错误。 |
| 409 监听冲突 | 保留表单，显示服务端原因。 |
| 412 版本过期 | 不覆盖最新规则，要求刷新。 |
| 请求失败 | 保留已有列表，允许重试。 |
| 空列表、筛选无结果 | 分别提供新增入口或清除筛选。 |
| 修改转发参数、停用或删除 | 明确说明会断开该规则现有会话。 |

## 5. 正常、基础与异常案例

- 正常：桌面表格与窄屏卡片可完成相同操作；TCP、UDP 与 TCP+UDP 标签清晰。桌面协议单选三列，窄屏 TCP/UDP 同行、TCP+UDP 独占下一行。
- 基础：名称、协议、监听 IP 与端口、目标主机与端口、启用状态组成完整输入。
- 异常：网络断开后仍可看到之前规则；会话过期不会一直留在不可操作页面。
- 无障碍：状态包含文字，按钮和表单有可访问名称，原生 dialog 管理焦点，删除默认焦点落在保留操作。

## 6. 必需验证

执行 `npm --prefix web run lint`、`type-check`、`test`、`build`；Vite build 不代替 TypeScript 检查。交互测试位于 `src/App.test.ts`，应以用户行为验证登录、CRUD、提交防重、字段错误、revision、CSRF、隐藏暂停轮询与过期退出。

组合交互测试断言单次新增请求携带 `tcp+udp`、一行一条计数、三种筛选包含关系、编辑回显与协议切换，以及整体启停删除。不因增加协议删除原有 TCP/UDP 用例。

必须实际浏览器检查窄屏。CSS 隐藏文字时，退出和刷新图标按钮必须保留显式 aria-label，不能只靠 SVG 或 title。对最终构建产物再执行 Go 构建，避免并发 npm build 清空 dist 导致 embed 失败。

## 7. 错误与正确写法

错误：`JSON.stringify({...rule, ...form})`，会把 id、status、revision 发给严格后端。

正确：只构造 RuleInput；revision 在 If-Match 头传递，运行态由后端返回。

错误：窄屏用 `display:none` 隐藏按钮中的 span，却没有 aria-label，导致按钮在辅助功能树中没有名称。

正确：退出按钮使用 `aria-label="退出登录"`，刷新使用 `aria-label="刷新规则"`，并保留相应回归断言。

错误：协议筛选直接使用 `rule.protocol === selectedProtocol`，导致组合规则在 TCP/UDP 下消失。

正确：使用 `matchesProtocol(rule.protocol, selectedProtocol)`，空值包含全部、组合筛选只含组合，单协议筛选同时包含相应单协议和组合。

源码依赖与锁文件同时更新；临时文件、npm 缓存、构建测试输出使用仓库 `.tmp/` 或被忽略的项目子目录，不访问系统临时目录。

## 8. 场景：流量展示与重置

### 8.1 范围与触发条件

修改规则统计开关、载荷字节展示、速度、重置或列表异步协调时适用。桌面与窄屏共享统计展示与格式化行为。

### 8.2 签名与边界

- RuleInput 增加 `traffic_enabled: boolean`，新增默认 false；Rule 包含只读 traffic 对象。
- `api.ts` 是统计响应校验的唯一边界；组件只能读取校验后的类型。
- 重置调用 `POST /api/admin/rules/{id}/traffic/reset` 或 `/api/user/rules/{id}/traffic/reset`，沿用内存 CSRF 与 If-Match，返回最新 Rule 后更新 revision。

### 8.3 数据与交互契约

累计字节 `upload_bytes/download_bytes` 是非负十进制字符串，格式化先用 BigInt，禁止先转为 Number 丢失精度。速度是有限非负数值，按 B/s 及二进制单位展示。上行指客户端到目标，下行反向，组合规则使用后端汇总，不另行相加。

编辑器的“流量统计”独立于“启用规则”；ruleInput、启停与编辑提交均保留此字段，不能回传 traffic。统计关闭显示关闭状态及保留的累计量，速度为零。

统计区提供重置按钮，关闭统计或停用规则时也能使用；弹窗确认会清零累计量但不影响连接，取消不请求。提交期间阻止重复，成功使用返回规则更新；操作前发起的旧轮询结果不得覆盖重置/保存后的快照。保持每 5 秒刷新与隐藏暂停行为。

### 8.4 校验与错误矩阵

| 条件 | 行为 |
| --- | --- |
| 缺失/非法统计字段、负值、NaN 或无限速度 | 解码拒绝，提示响应无效，保留已有列表。 |
| 重置失败 | 保留统计及弹窗可重试状态，不伪造清零成功。 |
| 过期版本 | 412 引导刷新，不自动重试覆盖。 |
| 会话过期 | 返回登录态。 |

### 8.5 正常、基础与异常案例

- 正常：真实持续转发时数值刷新，重置后重新累计，组合规则仅显示一套汇总。
- 基础：新增统计关闭、编辑回显、保留旧累计；重置按钮及弹窗在窄屏可用且有可访问名称。
- 异常：旧 GET 响应迟到不会恢复重置前数值；重置网络失败保留已有累计。

### 8.6 必需测试

行为测试覆盖默认值、开关序列化、编辑与启停保留开关、上下行与超安全整数格式、重置取消/成功/失败/412、防重复和旧轮询竞争。实际浏览器检查桌面与窄屏的统计区、重置确认、焦点和布局。

### 8.7 错误与正确写法

错误：`Number(rule.traffic.upload_bytes)` 后再格式化；只在已开启统计时允许重置；重置返回后让旧列表请求覆盖最新值。

正确：累计字节用 BigInt 格式化，统一组件同时用于表格与卡片；重置不依赖开关，使用请求序号或取消旧读取阻止迟到响应覆盖。

## 9. 场景：中英文界面与提示

### 9.1 范围与入口

新增或修改产品可见文案时适用，包括启动/登录、管理页、表单、确认弹窗、错误、通知、占位符、title 和 aria-label。内部会话、文档及注释保持中文。

登录表单保留 required 属性并使用 novalidate，由页面显示所选语言的缺失提示、聚焦相应输入并阻止请求；不能依赖浏览器原生校验气泡，其文案由浏览器 UI 语言决定。

### 9.2 签名与职责

- `src/i18n.ts`：`Language = "zh-CN" | "en"`，共享只读 `language`，提供 `initializeLanguage()`、`setLanguage(value)`、`t(key, params?)` 和 `knownMessage(message)`。
- `MessageKey` 从集中英文词典键推导，中文原文即词条键；插值参数通过 `t("共 {total} 条规则", { total })` 传递，不能按中文语序拼接英文。
- `src/components/LanguageSwitcher.vue`：统一切换入口，选项固定为“中文”和“English”，可访问名称随当前语言变化。
- `api.ts` 的 `errorMessage(error)`、`fieldErrorMessage(field, message)`、`ruleErrorMessage(rule)` 在展示时翻译；继续作为已校验错误与 UI 之间的边界。

### 9.3 语言与数据契约

偏好键为 `porter.language`。首次默认中文，合法持久值优先；读取异常或值无效时回到中文，写入异常不阻止当前页切换。初始化及切换同步 `html.lang`、文档标题和 description。语言变更不刷新页面、不发业务写请求，不清除输入、筛选或错误。

组件渲染或 computed 中调用翻译函数，使文案响应语言变化。持续显示的错误保留原始 ApiError 或原文键，成功通知保留词条键；不能在请求失败时缓存已经翻译的字符串。协议描述和状态标签同样在展示时翻译。

规则名、账号、地址、协议标识、字节单位及其他用户数据保持原值。语言偏好不存储 Cookie/CSRF，也不改变接口载荷、revision、轮询或流量精度。

### 9.4 错误矩阵

| 条件 | 行为 |
| --- | --- |
| 已知 API code | 映射当前语言提示；412 仍要求关闭表单并刷新。 |
| 字段原因 | 先识别已知原因，保留目标单播、IP、端口等不同约束。 |
| 监听失败 | 翻译后端有限模板，保留 TCP/UDP 诊断及停用后修改重叠地址的建议。 |
| 未知错误 | 显示当前语言的通用错误，不让原始未知中文泄漏到英文界面。 |
| 已显示错误时切换 | 原提示与对应字段立即更新，表单输入及焦点流程保留。 |
| localStorage 不可用 | 界面可用且可切换，本页语言仍生效。 |

### 9.5 场景与验证

默认中文；切换 English 后登录、列表及弹窗使用英文；刷新/退出登录仍保留语言。规则中文名称在英文页面仍为原名。桌面和窄屏中语言入口可达，长英文不遮挡操作。

新用例覆盖语言偏好、非法值和存储异常、英文客户端与服务端错误、已显示错误/通知切换、输入保留及元信息。共享语言状态与 localStorage 在每例前复位，避免污染原有中文业务用例。执行本规范第 6 节质量门禁，实际检查两种语言和窄屏。

### 9.6 错误与正确写法

错误：`error.value = t("操作失败，请稍后重试。")`，再直接渲染字符串，切换后仍显示旧语言。

正确：保留错误对象或词条键，在模板中调用 `errorMessage(error)` 或 `t(key)`；动态名称和计数使用词条参数，Vue 负责文本转义。


## 10. 场景：独立双端、所属用户与套餐界面

### 10.1 范围与入口

适用于管理端 /admin/、用户端 /user/ 的独立入口、身份、规则、套餐、用户及配置界面。两个入口由 Vite 多页面构建为 dist/admin/index.html 和 dist/user/index.html，Go 静态处理器显式映射合法深链接；生产根地址通过 302 跳转用户端 /user/，开发根页由 src/main.ts 加载固定用户端入口。未登录默认显示普通用户登录，显式 /admin/ 保留管理端。不能只修改 Go 跳转而遗漏开发首页，也不把 /api/* 错误兜底成前端首页。部署成功提示分别标明用户和管理员地址，不因改变默认入口而自动创建普通用户。

### 10.2 签名与模块职责

- createClient(role:Role) 固定 /api/admin 或 /api/user 请求前缀，每个客户端独立维护 setSession、onUnauthorized、CSRF 和 generation。AdminApp/UserApp 使用固定端实例，不通过隐藏按钮代替服务端鉴权。
- Session 包含 user_id、username、role 和 csrf_token，解码必须核对当前端角色。Rule 包含 owner_id，管理端必须有 owner={id,username,role}；输入不能展开响应对象。
- AdminResources 提供套餐与用户添加/查看、系统端口池配置；AccountOverview 展示普通用户自身套餐和当前周期；RuleEditor 复用字段，接收所属用户的端口边界和管理端可选归属。
- traffic.ts 提供精确字节及 GiB 转换，累计和额度通过 BigInt 处理；不使用 Number 字节后再计算或反向生成额度。

### 10.3 请求、响应与状态契约

管理端规则列表默认全部，所属用户在桌面表格和窄屏卡片均显示。表格使用命名 colgroup 管理列宽，管理端九列、用户端八列；空间不足整体横向滚动，不得沿用新增列前的 nth-child 宽度造成地址、统计和操作重叠。用户筛选包含管理员自己，以稳定 ID 请求 /api/admin/rules?owner_id=...，与原有名称/地址搜索、协议和状态组合。切换筛选使旧请求失效；任何旧结果、失败或 finally 都不能覆盖当前筛选或会话。

管理员新增规则可选择已有账号，POST 的专用输入附加 owner_id；编辑已有规则展示但锁定归属，更新只提交 RuleInput。所属用户为普通账号时显示并校验其分配端口，管理员本人无套餐范围；不能据操作者身份取消目标用户约束。管理端直接完成任意用户规则的全部现有操作，用户端仅请求本人接口，不提供跨账号选择。

管理端 plans 返回 {plans:Plan[]}，users 返回 {users:Account[]}，settings 返回 {port_start,port_end,revision}；未配置时两个端口为 0。Account={user,plan,usage}，字节为十进制字符串，UTC 时间为有效 RFC3339。全部 unknown 在 api.ts 校验，不在组件内重复 cast。

套餐支持 both/max/upload/download 四种计费及 calendar_month/anniversary/fixed_day 三种周期。固定日期时显示 1–31，其他模式提交 reset_day:null。单向准确标为“上下行较大值”，不是只上行；用量对全用户周期汇总。额度输入 GiB 且不能经浮点丢失字节精度。

用户概览显示分配范围、上下行、计费用量/额度、计费方式及下次 UTC 重置。quota_exceeded 与手动 disabled 和监听 error 分开显示；error + quota_reset_pending 使用独立双语提示并保留重试按钮；清零规则展示统计不能伪造套餐退款。

两端会话和 Cookie 独立，同浏览器同时登录可用，401、退出和旧请求失败只复位本端。客户端 generation 与页面 sessionVersion 同时保护旧请求：旧登录成功、旧写入 catch/finally、旧读取响应均不得污染新账号。修改类动作使用本端 CSRF 及适当 If-Match。

所有新增表单使用 novalidate 和本地已翻译字段提示，不能让浏览器原生气泡决定英文/中文提示。配置更新遇 412 保留错误并允许明确重新读取新 revision，不自动覆盖其他页面修改；刷新成功后才允许基于新版本再次保存。

### 10.3.1 页头导航

两个后台的页面导航位于共享页头内，桌面使用文字入口和 `aria-current="page"` 标记当前页面，不在正文重复按钮栏。宽度不超过 1100px 时通过有本地化名称、`aria-controls` 和 `aria-expanded` 的按钮展开导航；选择页面或按 Escape 收起并将焦点返回按钮。页面切换继续受 `mutationBusy` 保护，会话清理同时清空展开状态。保留原生按钮的 Tab、Enter 和 Space 行为，不为普通页面导航套用需要额外方向键协议的 ARIA menu 角色。

验证包括管理员与用户各自入口、选中态、展开/收起/焦点以及提交中的切页保护；桌面和 390px 窄屏实际检查两种界面语言，避免菜单与账户操作重叠。

### 10.4 校验与错误矩阵

| 条件 | 行为 |
| --- | --- |
| 管理规则缺失 owner、owner_id 不匹配、非法套餐/用量/UTC 字段 | 拒绝解码并保留原列表，不将未知数据写入页面。 |
| 普通用户端收到管理员 Session 或反之 | 会话无效，不能渲染另一端功能。 |
| 用户规则端口越界 | 表单字段错误并聚焦，服务端仍是权威校验方。 |
| 套餐用尽 | 显示额度状态和下次重置，操作失败保持真实规则状态。 |
| 系统配置 revision 过期 | 不自动覆盖；明确刷新取得新版本后可重试。 |
| 写操作后旧请求返回、旧会话401或失败 | 不清空新账号、不覆盖已更新资源、不复位新操作的 busy 状态。 |

### 10.5 正常、基础与异常案例

- 正常：管理员筛选 alice，只显示其规则；修改规则后 alice 用户端刷新看到新名称，管理端操作仍保留 alice 归属。
- 基础：同浏览器管理员与普通用户同时登录，退出用户端后刷新管理端仍为登录态；两种语言与 390px 窄屏均可操作。
- 异常：快速切换用户筛选，旧响应晚到不覆盖当前用户；配置保存 412 后手动刷新不会继续用旧 revision。

### 10.6 必需验证

在保留原有规则管理、组合协议、统计及双语行为测试基础上，增加双端固定前缀和 CSRF 独立、所属用户显示/筛选/代操作、越界拒绝、精确 GiB、套餐与用户表单、UTC 概览、配置冲突刷新、跨会话旧写入和迟到读取回归。实际浏览器验证管理与用户两端桌面/窄屏，两种语言，以及独立退出；生产构建后验证 Go 嵌入首页、深链接和 API 404。

### 10.7 错误与正确写法

错误：两个页面共用一个全局 csrf 或可切换 role 的请求对象；用完整 Rule 展开提交 owner；只在表格显示归属而遗漏窄屏卡片；在 catch 中无版本校验地清除新会话。

正确：固定角色入口绑定独立客户端实例，业务输入显式序列化；管理端专用创建输入只在创建时增加 owner_id；表格和卡片使用同一权威所属信息；读取和写入完成均核对当前请求/会话版本。

## 11. 场景：A 蓝白界面、用户列表与账户模式

### 11.1 范围与页面契约

双端统一采用蓝色字标、浅色背景、白色页头和横向导航。用户管理始终是一行一用户的八列表格，字段为用户名、套餐、分配端口、计费用量/额度、上行/下行、计费方式、重置方式、下次 UTC 重置。使用语义化表头、稳定 user.id、命名列宽及局部横向滚动；窄屏不把用户列表改回卡片。长名称省略时保留完整 title，英文长计费方式可换行。

规则页桌面累计量和速度分列，管理端九列、用户端八列；窄屏规则继续使用完整可操作的规则卡片。用户列表与规则列表的窄屏表示不能混为同一规则。

### 11.2 组件与工具签名

- AccountOverview 接收 account 与可选 compact；规则页传 compact，账户页使用完整分区并显示页面主标题。管理端用户列表不再逐个渲染账户卡。
- RuleTraffic 接收 rule、busy 和可选 mode（full/totals/speed），默认 full；桌面渲染 totals/speed，重置按钮只在 totals 中出现，窄屏只渲染 full。
- usagePercent(used: string, limit: string): number 读取已校验的非负十进制字节字符串；先以 BigInt 计算百分之一百分点，最后转换为0–100的有限展示值；零额度返回0、超限填充封顶100，实际累计与超限提示保留。
- formatUTC(value: string): string 统一格式化已校验时间；字节继续由 formatBytes 格式化，进度条不成为业务用量来源。
- Modal 接收 label/busy，规则编辑为居中原生 dialog；窄屏内容滚动、页脚可达，保留初始聚焦与关闭后焦点恢复。

### 11.3 添加用户表单与异步保护

标题右侧“添加用户”打开 Modal，复用原创建 API。打开时清除字段错误、账号与密码，并递增资源读取 version，使打开前的旧轮询响应、失败和 finally 无法污染新弹窗。弹窗打开期间暂停资源轮询；不能只暂停下一次读取而放任旧读取迟到。

提交期间父级 busy 禁止切页、关闭及退出；成功后更新列表、清空密码并关闭，失败保留输入和字段提示。取消/卸载清空密码，再次打开不回显旧密码。无套餐时显示提示并禁止提交。表单保持 novalidate、本地双语错误与首个错误聚焦。

### 11.4 状态与错误矩阵

| 情形 | 界面行为 |
| --- | --- |
| 用量接近或超过安全整数 | 比例计算不先转 Number，字节仍精确。 |
| 额度用尽 | 进度最多100%，真实用量与额度耗尽文字保留。 |
| 缺少套餐/用量 | 显示明确缺省，不构造套餐、周期或金额。 |
| 打开弹窗前的读取迟到 | 版本不匹配，忽略成功、失败和清理结果。 |
| 创建失败后经过多个轮询周期 | 输入和错误保留，可重试。 |
| 窄屏用户表格列多 | 仅表格容器横滚，页面和按钮不被撑宽。 |

### 11.5 场景与验证

accounts.test.ts 覆盖14行八列表格、缺省字段、添加用户打开/取消/成功/失败/防重、旧读取和轮询竞争、账户完整/紧凑模式。traffic.test.ts 覆盖零额度、超限及超过安全整数的临界比例。

界面改造除第6节检查外，必须在内置浏览器打开双端登录、全部业务页与编辑弹窗，对照设计稿保存桌面与390px截图；检查中英文、长名称、空态及真实提交。构建通过不等同于视觉验收通过，截图与合理偏差写入任务验证记录。

### 11.6 错误与正确写法

错误：Number(used)/Number(limit) 先损失精度；只暂停新轮询但旧失败仍进入弹窗；把生成图作为网页背景替代真实交互。

正确：BigInt 先算有界比例；打开弹窗递增 version 并暂停轮询；用真实组件实现布局，生成图只作为视觉依据。
